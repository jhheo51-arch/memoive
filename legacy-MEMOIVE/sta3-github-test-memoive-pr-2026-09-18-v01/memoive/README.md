# MEMOIVE v08 — 기록의 전체 순환과 내 기록 분석

실제 콘텐츠를 저장하고, 안전하게 옮기고, 모바일에서 다시 수집하고, 과거 기록과 연결해 재사용하는 전체 흐름을 갖춘 모바일 시제품입니다.

## 내 기록 분석

- 기록 유형별 개수와 가장 많이 쓰는 입력 방식 표시
- 저장한 기록을 사용자가 다시 연 비율 확인
- 나만의 생각을 추가한 기록 비율 확인
- 기록 상세에서 자동 요약을 `도움됐어요` 또는 `아쉬워요`로 평가
- 평가된 요약의 도움 비율과 글쓰기용 재활용 횟수 표시
- 행동 기록과 품질 평가는 외부 분석 서비스가 아니라 현재 기기에 저장
- 백업 파일에 분석 기록도 함께 포함하고, 가져올 때 기존 기록을 지우지 않고 병합

현재 비공개 Site는 소유자만 접근할 수 있으며, 분석 화면도 같은 접근 범위 안에 있습니다. 여러 테스트 사용자의 결과를 한곳에 모으는 기능은 계정·동의·분석 서버가 필요한 다음 단계입니다.

## 실제 링크 기록 방식

- 입력 직후 원문 주소와 사용자의 메모를 브라우저에 먼저 보존
- Jina AI Reader를 통해 공개 웹페이지 본문을 읽고 제목·발행일 확인
- 실제 원문 문장에서 핵심 내용 세 개를 선택해 요약과 근거를 함께 표시
- 본문을 읽지 못해도 주소와 메모를 유지하고 `원문 다시 읽기` 제공
- `http`와 `https` 주소만 허용하고 외부 전송 사실을 입력 화면에 안내
- 저장 날짜와 달력을 사용자의 현재 날짜에 맞게 표시

## 데이터 보관과 기기 이동

- 매번 저장하기 전 직전 데이터를 브라우저 안에 복구용 사본으로 보존
- 전체 기록을 JSON 백업 파일로 내려받기
- 다른 기기의 백업을 가져올 때 기존 기록을 지우지 않고 합치기
- 가져오는 주소와 데이터 구조를 검사해 잘못된 파일이나 위험한 주소 차단
- 현재 기록 수, 사용 공간, 마지막 백업 시각 표시

현재 GitHub Pages 구조에는 사용자 계정 서버가 없으므로 자동 클라우드 동기화를 흉내 내지 않습니다. 백업 파일을 통한 수동 동기화가 실제로 작동하는 첫 버전입니다.

## 모바일 수집과 재발견

- 설치형 웹앱 아이콘·범위·공유 대상 설정
- Android 공유 메뉴에서 받은 링크와 설명을 입력창에 자동 분리
- 오프라인에서는 주소부터 보존하고 온라인 복귀 시 실패한 원문 다시 읽기
- 사용자가 버튼을 눌렀을 때만 알림 권한 요청
- 알림이 허용된 기기에서는 앱을 열 때 다시 볼 기록 알림 표시

운영체제가 앱을 완전히 종료한 상태에서 보내는 원격 푸시 알림은 알림 서버가 필요하므로 현재 범위에 포함하지 않습니다.

## 기록 연결과 재활용

- 같은 주제나 반복된 핵심어를 기준으로 관련 기록 최대 3개 연결
- 기록을 다시 보여주는 이유를 홈과 상세 화면에서 설명
- 제목, 요약, 핵심 내용, 나의 기록, 태그, 원문을 Markdown 형식으로 복사
- 복사한 내용을 문서, 포트폴리오, 기획안의 초안으로 바로 재사용

## 검색 방식

- 상단 돋보기 버튼을 누르면 기록 서가의 검색창으로 바로 이동
- 제목, 출처, 요약, 내 생각, 주제를 현재 기기 안에서 즉시 검색
- 검색 결과 수를 화면과 화면 읽기 기능에 함께 안내
- `Esc` 키 또는 검색창의 기본 지우기 버튼으로 전체 기록 복원
- 검색 중에는 저장 데이터를 쓰거나 바꾸지 않음

## 이번 버전에 추가한 흐름

- 월간 달력의 날짜를 누르면 그날 기록 목록 표시
- 한 날짜에 여러 기록이 있으면 개수 배지 표시
- 관심 주제를 실제 기록에서 계산하고, 주제별 기록 열기
- 기록별 주제 추가·해제, 주제 이름 변경, 두 주제 병합
- 역할에 따라 질문을 다르게 제안하는 개인화 설정
- 같은 링크를 다시 저장할 때 중복을 감지하고 새 생각만 합치기
- 요약의 확신도, 원문 근거, 확인이 필요한 내용 표시
- 이미지 파일 선택과 추출 문자 확인·수정 흐름
- 브라우저 마이크 녹음 및 지원 환경의 음성 문자 변환 연결
- 음성·텍스트에서 다음 행동을 분리해 표시
- 3일·1주·한 달 뒤 재발견 시점 설정
- 설치형 웹앱의 공유 대상 설정과 공유 주소 자동 입력

## 중요한 범위 구분

현재 버전은 공개 웹페이지의 실제 본문을 가져오지만, 생성형 AI가 새 문장으로 요약하는 방식은 아닙니다. 원문에 있는 문장을 점수화해 고르는 `자동 정리`이므로 사실 근거를 직접 확인할 수 있고 별도 API 키가 필요하지 않습니다. 로그인 전용 페이지, 유료 콘텐츠, 접근을 막은 사이트는 주소만 보존될 수 있습니다. 링크 주소는 본문 변환을 위해 Jina AI Reader로 전송됩니다. 이미지·음성의 자동화 품질과 기기 간 동기화에는 이후 별도 서버 연결이 필요합니다.

## 확인 방법

```text
node tests/link-reader-self-check.mjs
node tests/data-tools-self-check.mjs
```

브라우저에서 `index.html`을 로컬 웹서버로 열고 공개 기사 주소를 입력하면 제목, 자동 정리, 핵심 문장, 원문 근거가 상세 화면에 표시됩니다.

## v09 영감 작업실

MEMOIVE의 핵심 흐름을 `정보 수집 → 자동 정리 → 나의 관점 → 결과물 → 재활용`으로 확장했습니다.

- 홈과 하단 `창작` 메뉴에서 영감 작업실 진입
- 기록 상세의 `결과물 만들기`로 현재 영감을 바로 선택
- 여러 기록을 한 결과물의 재료로 함께 선택
- 아이디어 메모, 블로그·뉴스레터, SNS 게시물, 업무 제안서, 프로젝트 기획안 지원
- 전달 목적과 나의 관점을 먼저 입력한 뒤 기록 기반 초안 생성
- 생성된 제목과 내용을 직접 수정하고 결과물로 별도 저장
- 결과물과 사용된 원본 기록을 다시 확인
- 결과물도 기존 기기 저장과 JSON 백업·가져오기에 포함
- 분석 화면에서 결과물 수와 영감→결과물 전환율 확인

초안은 외부 AI 서버를 사용하지 않고 선택한 기록과 사용자의 관점을 정해진 구조로 조합합니다. 따라서 실제 생성형 AI 연결 전에도 데이터 유출 없이 전체 창작 흐름을 검증할 수 있습니다.

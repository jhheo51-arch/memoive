# MOA — 콘텐츠를 지식으로 바꾸는 모바일 아카이브

> Portfolio Project / Mobile App PRD v0.1  
> 작성일: 2026-09-14  
> 문서 상태: MVP 정의

## 1. 제품 한 줄 소개

콘텐츠 링크를 저장하면 AI가 핵심 내용과 영감을 일정한 형식으로 정리하고, 주제별 지식 노트로 축적해주는 모바일 앱.

## 2. 배경과 문제

사람들은 아티클, 영상, 뉴스레터, SNS 게시물처럼 가치 있는 콘텐츠를 자주 발견한다. 그러나 대부분은 링크만 저장한 채 다시 읽지 않거나, 메모 앱마다 기록 방식이 달라 시간이 지나면 내용을 찾고 활용하기 어렵다.

### 사용자가 겪는 핵심 문제

1. 콘텐츠를 소비한 직후 직접 정리하는 데 시간이 많이 든다.
2. 링크만 저장하면 왜 저장했는지 기억하기 어렵다.
3. 기록 형식이 매번 달라 여러 노트를 비교하거나 연결하기 어렵다.
4. 폴더를 직접 고르는 일이 번거롭고, 하나의 콘텐츠가 여러 주제에 걸칠 수 있다.
5. 저장한 지식이 쌓여도 다시 발견하거나 실제 행동으로 이어지지 않는다.

### 해결 가설

링크를 입력하는 즉시 AI가 동일한 기준과 포맷으로 콘텐츠를 분석하고, 사용자는 짧은 검토만 거쳐 저장할 수 있다면 기록 부담이 줄고 저장한 콘텐츠의 재활용률이 높아질 것이다.

## 3. 제품 목표

### 사용자 목표

- 좋은 콘텐츠를 1분 안에 의미 있는 노트로 저장한다.
- 콘텐츠의 핵심, 새로운 관점, 활용 방법을 빠르게 파악한다.
- 저장한 노트를 주제별로 모아 자신의 관심사와 생각의 흐름을 확인한다.
- 과거에 저장한 내용을 필요한 순간에 다시 찾고 활용한다.

### 비즈니스·포트폴리오 목표

- AI가 장식이 아니라 핵심 사용자 문제를 해결하는 제품 경험을 설계한다.
- 모바일 환경의 빠른 캡처, 검토, 탐색 흐름을 보여준다.
- 정보 구조, AI 신뢰성, 개인화, 재방문 설계를 하나의 사례로 제시한다.

### MVP 성공 기준

- 신규 사용자의 60% 이상이 첫 세션에서 노트 1개를 저장한다.
- 링크 입력 후 저장 완료까지 걸리는 시간 중앙값이 60초 이하이다.
- AI 초안의 70% 이상이 큰 수정 없이 저장된다.
- 저장 후 7일 이내 노트를 다시 열어본 사용자 비율이 30% 이상이다.

## 5. 제품 원칙

1. **저장보다 이해** — 링크 수집이 아니라 핵심을 파악하고 남기는 데 초점을 둔다.
2. **AI 초안, 사용자 판단** — AI가 정리하되 최종 의미와 보관 여부는 사용자가 결정한다.
3. **일관된 기록** — 모든 노트가 같은 구조를 가져 빠르게 훑고 비교할 수 있어야 한다.
4. **분류보다 연결** — 하나의 폴더를 강요하지 않고 여러 주제 태그로 연결한다.
5. **다시 쓰이는 지식** — 저장 완료보다 재발견과 활용을 중요한 가치로 본다.

## 7. 핵심 사용자 흐름

### A. 링크 저장

1. 사용자가 앱의 `+` 버튼을 누르거나 다른 앱의 공유 메뉴에서 MOA를 선택한다.
2. URL이 자동 입력되고 사용자가 `분석하기`를 누른다.
3. 앱이 제목, 출처, 대표 이미지, 콘텐츠 유형을 추출한다.
4. AI가 콘텐츠 품질과 핵심 내용을 분석한다.
5. 사용자가 생성된 노트를 검토하고 필요하면 수정한다.
6. 추천 주제를 선택하거나 새 주제를 추가한다.
7. `저장`을 누르면 노트가 라이브러리에 추가된다.

### B. 저장한 지식 다시 찾기

1. 사용자가 홈에서 최근 노트 또는 주제를 선택한다.
2. 노트 목록을 훑거나 검색어를 입력한다.
3. 노트 상세에서 핵심 요약, 영감 포인트, 실행 아이디어를 확인한다.
4. 필요하면 원문을 다시 열거나 즐겨찾기한다.

## 8. 좋은 콘텐츠의 기준

AI는 콘텐츠의 인기도가 아니라 **사용자에게 남길 가치**를 평가한다. 평가는 노트를 버리기 위한 절대 판정이 아니라, 사용자가 읽을 우선순위를 정하도록 돕는 신호다.

### 평가 항목

| 항목 | 질문 | 점수 |
|---|---|---:|
| 구체성 | 주장에 사례, 근거, 데이터 또는 방법이 포함되어 있는가? | 0~2 |
| 새로움 | 흔한 이야기의 반복을 넘어 새로운 관점이나 연결을 제공하는가? | 0~2 |
| 활용성 | 업무, 학습, 창작 또는 의사결정에 적용할 수 있는가? | 0~2 |
| 신뢰성 | 출처와 논리가 분명하며 과장이나 비약이 적은가? | 0~2 |
| 개인 적합성 | 사용자의 관심 주제 및 저장 목적과 관련이 있는가? | 0~2 |

### 등급

- **8~10점 · 꼭 남길 콘텐츠** — 다시 볼 이유와 활용 가능성이 분명함
- **5~7점 · 참고할 콘텐츠** — 유용하지만 일부 내용이 평범하거나 근거가 약함
- **0~4점 · 가볍게 볼 콘텐츠** — 정보 밀도나 신뢰도가 낮음

### UX 표현 원칙

- 총점보다 `왜 가치 있는지`를 한 문장으로 먼저 보여준다.
- 낮은 점수여도 저장을 막지 않는다.
- 신뢰성 판단이 어려우면 단정하지 않고 `확인 필요`로 표시한다.
- 개인화 데이터가 충분하지 않은 초기에는 개인 적합성을 중립값으로 처리한다.

## 9. 표준 요약 형식

모든 노트는 다음 구조를 사용한다.

1. **한 줄 핵심** — 콘텐츠 전체를 1~2문장으로 압축
2. **핵심 내용** — 가장 중요한 주장 또는 정보 3개
3. **영감 포인트** — 기존 생각과 다른 관점이나 기억할 만한 연결 1~3개
4. **활용 아이디어** — 사용자가 실제로 시도할 수 있는 행동 1~3개
5. **확인할 점** — 근거가 약하거나 추가 검증이 필요한 주장
6. **주제** — 상위 주제 1~3개와 세부 태그 0~5개
7. **출처 정보** — 제목, 작성자/채널, 발행일, 원문 URL

### 요약 작성 원칙

- 원문의 주장과 AI의 해석을 섞지 않는다.
- 사실, 의견, 추론을 구분한다.
- 원문에 없는 숫자와 사례를 만들지 않는다.
- 불필요한 배경 설명과 반복을 제거한다.
- 전문 용어는 유지하되 짧게 풀어쓴다.
- 읽는 데 1분을 넘기지 않는 분량을 기본으로 한다.

## 10. AI 시스템 프롬프트 초안

```text
역할:
당신은 사용자가 콘텐츠를 다시 활용할 수 있는 지식 노트로 바꾸는 편집자다.

목표:
입력된 콘텐츠를 정확하게 이해하고, 아래 고정 형식에 맞춰 간결한 한국어 노트를 만든다.

평가 원칙:
- 구체성, 새로움, 활용성, 신뢰성, 개인 적합성을 각각 0~2점으로 평가한다.
- 점수마다 콘텐츠 속 근거를 한 문장으로 설명한다.
- 인기도, 문체, 작성자의 유명세만으로 높은 점수를 주지 않는다.
- 판단할 정보가 없으면 추측하지 말고 "확인 어려움"이라고 쓴다.

출력 형식:
1. 한 줄 핵심: 120자 이내
2. 핵심 내용: 정확히 3개, 각 100자 이내
3. 영감 포인트: 1~3개
4. 활용 아이디어: 1~3개, 동사로 시작
5. 확인할 점: 없으면 빈 배열
6. 품질 평가: 항목별 점수와 근거, 총점, 등급
7. 추천 주제: 상위 주제 1~3개, 세부 태그 0~5개
8. 메타데이터: 제목, 작성자/채널, 발행일, 콘텐츠 유형

안전 규칙:
- 원문에 없는 사실, 인용문, 수치, 출처를 생성하지 않는다.
- 원문의 사실과 작성자의 의견을 구분한다.
- AI의 해석은 "영감 포인트" 또는 "활용 아이디어"에만 작성한다.
- 콘텐츠를 충분히 읽을 수 없으면 실패 이유와 사용자가 할 수 있는 조치를 반환한다.

출력:
화면 렌더링이 가능한 구조화된 JSON만 반환한다.
```

## 11. 정보 구조

- **홈** — 오늘의 재발견, 최근 저장, 자주 보는 주제

- 원문 메타데이터
- 표준 요약 전체

## 13. 기능 요구사항

### 링크 입력 및 추출

- 유효한 `http/https` URL만 분석 요청할 수 있어야 한다.
- 이미 저장된 URL이면 중복 안내와 기존 노트 열기 옵션을 제공해야 한다.
- 본문 접근이 불가능하면 원인을 설명하고 직접 텍스트 입력 옵션을 안내해야 한다.
- YouTube 영상은 자막이 있을 때만 MVP 분석을 지원한다.

### AI 분석

- 분석 결과는 표준 스키마로 반환되어야 한다.
- 사용자는 모든 텍스트 필드와 주제를 수정할 수 있어야 한다.
- 분석 결과에 근거가 부족한 내용은 `확인 필요`로 표시해야 한다.
- 실패 시 재시도할 수 있고 중복 노트가 생성되지 않아야 한다.

### 분류

- 하나의 노트에 여러 주제를 연결할 수 있어야 한다.
- AI는 기존 주제를 우선 추천해 유사 주제의 중복 생성을 줄여야 한다.
- 사용자는 주제를 추가, 이름 변경, 병합할 수 있어야 한다.

### 검색 및 탐색

- 제목, 한 줄 핵심, 핵심 내용, 태그를 통합 검색해야 한다.
- 검색 결과는 입력과 동시에 갱신되어야 한다.
- 필터를 여러 개 조합할 수 있어야 한다.

### 재발견

- 홈에 과거 노트 1개를 보여준다.
- 최근에 열지 않았고 사용자의 관심 주제와 관련된 노트를 우선한다.
- 사용자가 숨긴 노트는 다시 추천하지 않는다.

## 14. 비기능 요구사항

- 첫 화면은 일반적인 모바일 네트워크에서 2초 이내 표시한다.
- 링크 분석 요청 후 즉시 진행 상태를 보여준다.
- 분석이 길어질 경우 백그라운드 처리하고 완료 상태를 앱 내에서 알린다.
- 개인정보와 저장 콘텐츠는 전송·보관 시 암호화한다.
- 삭제한 노트는 30일간 복구 가능하게 한 뒤 영구 삭제한다.
- 원문 전체를 영구 복제하지 않고 서비스 제공에 필요한 최소 데이터만 저장한다.
- 접근성: 동적 글자 크기, 충분한 색 대비, 스크린리더 레이블을 지원한다.

## 19. 검증 계획

### 사전 인터뷰

- 대상: 콘텐츠를 주 5개 이상 저장하는 사용자 5명
- 확인할 것: 현재 저장 경로, 기록 포기 시점, 다시 찾는 상황, AI 요약 신뢰 조건

### 사용성 테스트

- 과제 1: 최근 본 아티클을 링크로 저장하기
- 과제 2: AI가 만든 요약을 수정하고 주제 선택하기
- 과제 3: 일주일 전에 저장한 특정 노트 다시 찾기
- 관찰 지표: 완료 여부, 소요 시간, 막힌 지점, 결과 신뢰도

### 핵심 가설 실험

1. 고정 템플릿이 자유 요약보다 훑어보기 쉽다.
2. 숫자 점수보다 가치 이유 한 문장이 저장 판단에 더 유용하다.
3. 자동 저장보다 검토 후 저장이 AI에 대한 신뢰를 높인다.
4. 폴더 하나보다 복수 주제 태그가 콘텐츠 탐색에 적합하다.

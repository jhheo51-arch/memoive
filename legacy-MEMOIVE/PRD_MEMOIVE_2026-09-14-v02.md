## 1. 제품 개요

### 브랜드

**MEMOIVE / 메모이브**

- 합성 의미: `Memo + Alive`
- 브랜드 뜻: 저장해둔 콘텐츠와 생각을 다시 살아 움직이게 한다.
- 슬로건: **저장한 생각을 다시 살아나게.**

### 한 줄 소개

콘텐츠, 유튜브, 기사, 이미지 레퍼런스를 발견하는 순간 빠르게 저장하고, AI의 도움으로 내 생각까지 남겨 나중에 다시 꺼내 쓰게 하는 모바일 기록 앱.

### 핵심 명제

> 사람들은 정보를 찾지 못해서가 아니라, 본 것을 자신의 생각으로 남기지 못해서 잊는다.

## 2. 문제 정의

### 배경

사용자는 하루에도 수많은 기사, 영상, SNS 게시물, 디자인 이미지와 업무 레퍼런스를 접한다. 좋은 내용은 북마크, 스크린샷, 나에게 보내기, 메모 앱 등 여러 장소에 저장되지만 시간이 지나면 무엇을 저장했는지, 왜 중요했는지 기억하기 어렵다.

### 사용자의 핵심 문제

1. 콘텐츠를 발견한 순간 직접 정리하기에는 시간이 부족하다.
2. 링크와 스크린샷만 남기면 저장한 이유를 잊는다.
3. 요약만 저장하면 콘텐츠는 남지만 사용자의 생각은 남지 않는다.
4. 기록 장소와 형식이 제각각이라 필요한 순간 다시 찾기 어렵다.
5. 저장한 자료가 다시 노출되지 않아 실제 글쓰기나 프로젝트에 활용되지 않는다.
6. 매일 긴 글을 써야 한다는 부담 때문에 기록 습관을 포기한다.

### 해결 가설

사용자가 콘텐츠를 발견한 순간 10초 안에 저장할 수 있고, AI가 내용을 이해하기 쉽게 정리한 뒤 부담 없는 질문 하나로 사용자의 생각을 덧붙이게 한다면, 저장한 정보가 기억과 활용 가능한 기록으로 전환될 것이다.

## 3. 제품 목표와 비목표

### 제품 목표

- 어떤 앱을 사용 중이든 콘텐츠를 즉시 저장할 수 있게 한다.
- 원문, AI 정리, 나의 기록을 명확히 구분한다.
- 사용자가 한 문장만으로도 기록을 시작할 수 있게 한다.
- 과거 기록을 현재 관심사와 연결해 다시 보여준다.
- 축적한 기록을 글, 아이디어, 프로젝트에 활용하게 한다.
- 기록 횟수보다 다시 꺼내 쓴 기록의 수를 늘린다.

### MVP 비목표

- 새로운 콘텐츠를 추천하는 피드 서비스
- AI가 사용자를 대신해 모든 생각을 완성하는 서비스
- 정확한 지식 암기를 위한 학습 앱
- 팀 문서 관리나 협업 도구
- 공개 팔로우·좋아요 중심의 소셜 서비스
- 무조건 매일 접속하게 만드는 출석 앱

## 4. 핵심 타깃

### 1차 타깃

- 20~39세 기획자, 디자이너, 마케터, 창작자, 연구·학습자
- 업무와 관심사를 위해 기사, 유튜브, SNS, 이미지 레퍼런스를 자주 저장함
- 스크린샷, 북마크, 메모 앱에 정보가 흩어져 있음
- 기록 욕구는 높지만 분류와 정리에 부담을 느낌

### 대표 사용자

**29세 프로덕트 디자이너**

- 출퇴근 중 디자인 사례와 유튜브 인터뷰를 자주 본다.
- 인상적인 화면은 스크린샷으로, 기사는 브라우저 북마크로 저장한다.
- 프로젝트를 시작할 때 과거에 본 레퍼런스를 다시 찾지 못한다.
- 긴 노트보다 당시의 생각과 활용 이유를 빠르게 남기고 싶다.

### 해야 할 일

> 좋은 콘텐츠나 레퍼런스를 발견했을 때, 흐름을 방해받지 않고 저장하고, 나중에 기억하고 활용할 수 있도록 그때의 생각까지 남기고 싶다.

## 5. 제품의 핵심과 보조 장치

### 핵심: 상시 기록

사용자가 좋은 자료를 발견하는 시점은 정해져 있지 않다. 따라서 기록은 특정 요일이나 알림 시간에만 하는 활동이 아니다. 앱 안팎에서 항상 기록할 수 있어야 한다.

상시 기록 진입점은 다음과 같다.

1. 다른 앱의 모바일 공유 메뉴에서 MEMOIVE 선택
2. 앱 모든 주요 화면의 `+ 기록` 버튼
3. 홈의 링크 붙여넣기
4. 홈 화면 위젯의 빠른 기록
5. 텍스트·음성으로 떠오른 생각만 기록
6. 사진 또는 스크린샷 가져오기

### 보조: 주 3회 기록 리듬

주 3회 질문형 알림은 새로운 콘텐츠 저장을 강요하지 않는다. 이미 저장했지만 생각을 남기지 않은 자료를 완성하거나, 과거 기록을 다시 발견하도록 돕는다.

우선순위는 항상 다음과 같다.

`상시 저장 가능성 > 기록 완성 지원 > 주기적 재발견`

## 6. 제품 차별화

### 시장의 일반적인 흐름

`콘텐츠 저장 → AI 요약 → 자동 분류 → 검색 또는 대화`

### MEMOIVE의 흐름

`발견 → 10초 저장 → AI 이해 보조 → 나의 한 줄 → 관련 기록 연결 → 재발견 → 활용`

### 여섯 가지 차별점

1. **나의 기록 우선**  
   AI 요약보다 사용자가 남긴 생각, 질문, 동의·반박, 활용 의도를 더 중요하게 보여준다.

2. **질문하는 AI**  
   답을 완성하는 대신 콘텐츠에 맞는 질문 하나를 건네 사용자의 생각을 끌어낸다.

3. **점진적 기록**  
   발견 순간에는 링크만 저장할 수 있고, 나중에 한 줄 생각과 연결을 단계적으로 추가한다.

4. **생각의 변화**  
   같은 주제에 관해 과거에 남긴 생각과 현재 생각을 비교할 수 있다.

5. **개인 기록 리듬**  
   매일 출석을 강요하지 않고 사용자가 선택한 빈도와 시간에 부담 없는 질문을 제공한다.

6. **재발견에서 활용으로**  
   과거 기록을 보여주는 데서 멈추지 않고 글, 프로젝트 메모, 아이디어 묶음으로 발전시킨다.

## 7. 제품 원칙

1. **기록을 멈추게 하지 않는다** — 저장 순간에는 필수 입력을 최소화한다.
2. **한 문장이면 충분하다** — 긴 글을 써야 기록으로 인정되는 분위기를 만들지 않는다.
3. **AI와 나를 구분한다** — AI 생성 내용과 사용자 작성 내용을 시각적으로 구분한다.
4. **기억보다 맥락을 남긴다** — 무엇을 저장했는지뿐 아니라 왜 저장했는지를 남긴다.
5. **알림은 재촉보다 계기다** — 죄책감과 불안 대신 시작할 질문을 제공한다.
6. **저장보다 재활용을 측정한다** — 많이 모으는 것보다 다시 꺼내 쓰는 것을 성공으로 본다.

## 8. 기록의 구조

하나의 기록은 네 층으로 구성한다.

### 1층: 원본

- 콘텐츠 제목
- 원문 링크 또는 이미지
- 작성자·채널·출처
- 발행일
- 콘텐츠 유형
- 저장일

### 2층: AI 정리

- 한 줄 핵심
- 핵심 내용 3개
- 기억할 만한 근거 또는 장면
- 확인이 필요한 내용
- 추천 주제

### 3층: 나의 기록

- 왜 저장했나요?
- 가장 인상적인 부분은 무엇인가요?
- 동의하거나 다르게 생각한 점이 있나요?
- 어디에 활용하고 싶나요?
- 자유 메모 또는 음성 기록

사용자는 모든 질문에 답할 필요가 없다. 기본 화면에는 콘텐츠에 가장 적합한 질문 하나만 보여준다.

### 4층: 연결과 활용

- 관련된 과거 기록
- 연결된 주제
- 프로젝트 또는 아이디어 묶음
- 이후 실행할 일
- 글쓰기 초안에 사용 여부

## 10. 핵심 사용자 흐름

### 흐름 A: 콘텐츠를 발견한 순간 빠르게 저장

1. 사용자가 브라우저, YouTube, SNS 또는 사진 앱에서 공유 버튼을 누른다.
2. MEMOIVE를 선택한다.
3. 미리보기와 `저장` 버튼이 표시된다.
4. 사용자가 즉시 저장하거나 한 줄을 덧붙인다.
5. 앱은 백그라운드에서 내용을 분석한다.
6. 저장 완료 메시지를 보여주고 원래 사용하던 앱으로 돌아간다.

**목표 시간:** 링크 공유부터 저장 완료까지 10초 이내

### 흐름 B: 앱 안에서 기록 완성

1. 사용자가 최근 저장 기록을 연다.
2. AI 한 줄 핵심과 원문 정보를 확인한다.
3. 콘텐츠에 맞는 질문 하나가 표시된다.
4. 텍스트 또는 음성으로 답한다.
5. AI가 기존 주제와 관련 기록을 제안한다.
6. 사용자가 연결을 확인하고 기록을 완료한다.

### 흐름 C: 질문형 알림으로 기록 이어가기

1. 사용자가 온보딩에서 주 3회와 선호 시간을 선택한다.
2. 앱은 아직 생각을 남기지 않은 저장 기록을 찾는다.
3. 콘텐츠 제목과 질문이 포함된 알림을 보낸다.
4. 사용자가 알림을 누르면 해당 기록의 한 줄 입력 화면이 열린다.
5. 한 문장을 남기면 이번 주 기록 진행도가 갱신된다.

### 흐름 D: 과거 기록 재발견

1. 홈에 현재 관심 주제와 연결되는 과거 기록이 표시된다.
2. 사용자가 과거의 나의 기록을 확인한다.
3. `지금은 어떻게 생각하나요?` 질문에 새 생각을 추가한다.
4. 과거와 현재의 생각을 시간순으로 확인한다.

### 흐름 E: 기록 활용

1. 사용자가 주제 또는 여러 기록을 선택한다.
2. `활용하기`를 누른다.
3. 글감 정리, 프로젝트 참고자료, 실행 목록 중 하나를 선택한다.
4. AI가 원본 출처와 사용자 기록을 구분해 초안을 만든다.
5. 사용자가 편집하거나 외부로 내보낸다.

## 11. 질문형 AI 설계

### 질문 생성 원칙

- 한 번에 질문 하나만 제시한다.
- 원문에 답이 있는 독해 문제를 묻지 않는다.
- 사용자의 판단, 경험, 연결, 활용을 묻는다.
- 30초 안에 답할 수 있어야 한다.
- 답하지 않고 건너뛸 수 있어야 한다.
- 이전 답변과 같은 질문을 반복하지 않는다.

### 질문 유형

| 목적 | 질문 예시 |
|---|---|
| 저장 이유 | 이 콘텐츠를 남기고 싶었던 이유는 무엇인가요? |
| 인상 | 가장 오래 기억하고 싶은 부분은 무엇인가요? |
| 관점 | 기존 생각과 달랐던 점이 있나요? |
| 비판 | 동의하기 어려운 부분도 있나요? |
| 연결 | 최근 고민과 어떤 관련이 있나요? |
| 활용 | 어디에 한 번 적용해보고 싶나요? |
| 변화 | 예전 기록과 비교하면 지금 생각은 어떻게 달라졌나요? |

### 질문 선택 우선순위

1. 사용자가 저장할 때 남긴 짧은 문장과 관련된 질문
2. 콘텐츠 내용과 사용자의 관심 주제를 연결하는 질문
3. 비슷한 과거 기록과 비교하는 질문
4. 정보가 부족하면 범용적인 저장 이유 질문

## 12. 기록 리듬과 알림

### 기본값

- 추천 빈도: 주 3회
- 사용자가 요일과 시간을 변경할 수 있음
- 매일, 주 1회, 주 3회, 주말 정리, 알림 끄기 제공
- 앱 첫 가치를 경험한 뒤 알림 사용 여부를 요청

### 알림 우선순위

1. 저장했지만 나의 기록이 없는 콘텐츠
2. 사용자가 다시 보기로 지정한 콘텐츠
3. 현재 관심 주제와 연결되는 과거 기록
4. 이번 주 기록 리듬을 마무리할 수 있는 가벼운 질문

### 알림을 보내지 않는 조건

- 사용자가 오늘 이미 기록한 경우
- 최근 알림을 연속으로 무시한 경우
- 방해 금지 시간
- 분석 실패 또는 원문 접근이 불가능한 콘텐츠만 남은 경우
- 사용자가 해당 콘텐츠를 숨긴 경우

### 메시지 원칙

- `기록하세요`보다 구체적인 질문을 사용한다.
- 콘텐츠 제목 또는 과거 기록의 맥락을 포함한다.
- 연속 기록 손실을 위협하지 않는다.
- 복귀 사용자에게 놓친 기록을 채우라고 요구하지 않는다.
- 알림을 누르면 해당 질문 화면으로 바로 이동한다.

### 진행 표현

- 매일 연속 기록 숫자보다 `이번 주 2/3`을 기본으로 표시한다.
- 목표를 넘기면 추가 기록 수를 긍정적으로 보여준다.
- 한 주를 놓쳐도 누적 기록과 과거 성취는 유지한다.

## 15. MVP 기능 요구사항

### 빠른 저장

- 유효한 링크, 이미지, 스크린샷, 텍스트, 음성을 저장할 수 있어야 한다.
- 모바일 공유 메뉴에서 10초 이내 저장할 수 있어야 한다.
- AI 분석이 실패해도 원본과 사용자의 메모는 보존되어야 한다.
- 동일 링크가 이미 있으면 기존 기록에 추가할지 새 맥락으로 저장할지 선택할 수 있어야 한다.

### AI 분석

- 원문과 AI 생성 내용을 구분해 저장해야 한다.
- 콘텐츠를 충분히 읽지 못하면 추측하지 않고 접근 범위를 표시해야 한다.
- 콘텐츠에 없는 수치, 인용, 출처를 생성하지 않아야 한다.
- 핵심 내용은 기본 3개 이내로 제한해야 한다.
- 사용자가 AI 결과를 수정하거나 다시 생성할 수 있어야 한다.

### 나의 기록

- 사용자는 링크 저장 시 메모를 생략할 수 있어야 한다.
- 텍스트와 음성으로 생각을 추가할 수 있어야 한다.
- AI가 작성한 문장을 사용자 문장처럼 표시해서는 안 된다.
- 하나의 원본에 여러 시점의 생각을 추가할 수 있어야 한다.

### 분류와 연결

- 하나의 기록을 여러 주제에 연결할 수 있어야 한다.
- AI는 새 주제를 만들기 전에 기존 주제를 먼저 추천해야 한다.
- 관련 기록을 추천한 이유를 짧게 보여줘야 한다.
- 사용자는 추천 연결을 승인하거나 거절할 수 있어야 한다.

### 알림

- 사용자가 빈도, 요일, 시간, 알림 유형을 변경할 수 있어야 한다.
- 사용자가 오늘 기록을 완료하면 예정된 재촉 알림을 취소해야 한다.
- 알림을 누르면 일반 홈이 아닌 대상 기록과 질문으로 이동해야 한다.
- 알림을 끈 사용자의 기록 기능에는 제한이 없어야 한다.

### 검색과 활용

- 제목, 출처, AI 요약, 나의 기록, 주제를 통합 검색해야 한다.
- 검색 결과에서 AI 내용과 사용자 내용을 구분해 보여줘야 한다.
- 여러 기록을 선택해 하나의 아이디어 묶음으로 만들 수 있어야 한다.
- 원문 출처를 유지한 상태로 기록을 내보낼 수 있어야 한다.

## 16. AI 출력 형식

```text
역할:
당신은 콘텐츠를 사용자의 생각으로 연결하도록 돕는 기록 편집자다.

목표:
원문을 정확하게 정리하고, 사용자가 짧게 답할 수 있는 성찰 질문 하나를 만든다.

2. 핵심 내용: 최대 3개
3. 기억할 근거 또는 장면: 최대 2개
4. 확인할 점: 근거가 약하거나 접근하지 못한 내용
5. 추천 주제: 기존 주제 우선, 최대 3개
6. 관련 기록: 추천 이유를 포함해 최대 3개
7. 사용자 질문: 판단·경험·연결·활용을 묻는 질문 정확히 1개

규칙:
- 원문에 없는 사실, 숫자, 인용문을 만들지 않는다.
- 원문의 주장과 AI의 해석을 구분한다.
- 사용자 질문에 대한 답을 대신 작성하지 않는다.
- 기존 사용자 기록을 수정하거나 덮어쓰지 않는다.
- 원문 접근이 불충분하면 분석 범위와 실패 이유를 표시한다.
- 화면에서 처리할 수 있는 구조화된 데이터로 반환한다.
```

## 21. MVP 성공 기준

- 신규 사용자의 60% 이상이 첫 세션에서 첫 기록을 저장한다.
- 모바일 공유 메뉴 저장 시간 중앙값이 10초 이하이다.
- 저장한 원본의 95% 이상이 AI 실패와 관계없이 보존된다.
- 저장 기록의 40% 이상에 7일 안에 사용자 생각이 추가된다.
- 질문형 알림을 연 사용자의 35% 이상이 한 줄 기록을 완료한다.
- 활성 사용자의 30% 이상이 매주 과거 기록을 한 번 이상 재활용한다.

## 23. 검증 계획

### 사용자 인터뷰

- 콘텐츠를 주 5개 이상 저장하는 사용자 5명
- 저장 장소와 다시 찾지 못했던 경험 확인
- 저장 당시 한 줄을 남길 의향과 방해 요소 확인
- 매일 기록과 주간 기록 리듬에 대한 부담 비교

### 사용성 과제

1. YouTube 앱에서 영상을 MEMOIVE에 저장한다.
2. 공유 저장창에서 10초 안에 저장을 완료한다.
3. 저장한 기사에 질문을 보고 한 줄 생각을 남긴다.
4. 일주일 전 저장한 디자인 레퍼런스를 찾는다.
5. 관련된 두 기록을 하나의 주제로 연결한다.

### 먼저 검증할 가설

1. 저장 단계의 메모 입력을 선택 사항으로 두면 저장 완료율이 높아진다.
2. 일반적인 `기록해주세요`보다 콘텐츠 제목이 포함된 질문형 알림이 기록 완료율을 높인다.
3. AI 요약보다 나의 한 줄을 위에 배치하면 사용자 기록의 중요성이 커진다.
4. 매일 연속 기록보다 주 3회 목표가 부담 없이 지속하기 쉽다.
5. 과거 기록과의 연결이 단순 재노출보다 활용 행동을 더 많이 만든다.

## 24. 수익 모델 가설

### 무료

- 월간 기본 저장 수
- 기본 AI 정리
- 나의 기록과 검색
- 기본 질문형 알림

### 유료 구독

- 저장 및 AI 분석 한도 확대
- 이미지·음성·PDF 등 확장 형식
- 기록 간 고급 연결
- 주제별 브리핑과 글쓰기 활용
- 외부 서비스 내보내기
- 장기 기록 변화 분석

MVP에서는 결제보다 반복 사용 가치 검증을 우선한다.

## 25. 포트폴리오에서 보여줄 핵심 이야기

### 문제 재정의

초기에는 AI 링크 요약 서비스로 시작했지만 경쟁 조사를 통해 요약과 자동 분류만으로는 차별화가 약하다는 사실을 확인했다.

### 중요한 설계 결정

- 저장 앱에서 생각 기록 앱으로 중심 이동
- 매일 강제 출석 대신 상시 저장과 주 3회 보조 리듬 결합
- AI 자동 완성 대신 질문형 AI 채택
- AI 요약과 사용자 생각의 명확한 구분
- 저장량 대신 재활용 기록을 핵심 지표로 선택

### 포트폴리오 산출물

- 문제 정의 변화 과정
- 경쟁 서비스 비교
- 사용자 인터뷰와 가설 지도
- 상시 저장 사용자 여정
- 모바일 정보 구조와 화면 흐름
- 질문형 알림 문구 실험
- AI 요약과 사용자 기록 구분 방식
- 사용성 테스트 전후 개선 결과

## 26. 결정된 사항

- 브랜드: MEMOIVE / 메모이브
- 최종 제품 형식: iOS·Android 모바일 앱
- 제품의 핵심: 콘텐츠 발견 순간의 상시 기록
- 습관 보조: 부담 없는 질문형 알림
- 추천 기록 리듬: 주 3회, 사용자 변경 가능
- AI 역할: 요약과 분류만이 아니라 사용자의 생각을 끌어내는 질문 제공

## 27. 다음 단계

1. 핵심 사용자 흐름을 모바일 화면 단위로 정리한다.
2. `공유 저장 → 한 줄 기록 → 재발견` 세 흐름의 낮은 완성도 화면 설계안을 만든다.
3. 실제 기사, YouTube, 이미지 레퍼런스 각각 2개로 AI 출력과 질문을 시험한다.
4. 5명의 잠재 사용자에게 저장 시간과 질문 부담을 검증한다.
5. 검증 결과를 반영해 MVP 화면 범위를 확정한다.

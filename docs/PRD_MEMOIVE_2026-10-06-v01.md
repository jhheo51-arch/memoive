## 1. 제품 정의와 문제
**흘러가는 정보를 영감으로, 영감을 결과물로.**

MEMOIVE는 북마크 목록을 넘어, 저장한 정보에 내 생각을 붙이고 다시 찾아 편집 가능한 글·기획안으로 연결하는 개인 창작 시스템의 웹 시제품입니다.

문제 가설은 “저장한 콘텐츠의 의미를 잊고, 필요한 순간 찾거나 작업에 활용하기 어렵다”입니다. 정보 과잉 전체보다 저장 이후의 단절에 집중합니다. 초기 사용자는 제품 사례를 모아 기획안·포트폴리오를 만드는 PM/PO·컨설팅 직무 준비자입니다. 제작자의 관심과 맥락에서 시작했으며 이 집단의 대표 수요가 인터뷰로 검증된 것은 아닙니다.

성공 방향은 저장 개수 증가가 아니라 **직접 남긴 생각을 다시 찾아 결과물에 활용하고 그 근거를 남기는 것**입니다. 수치 목표와 실제 사용 효과는 아직 확정하지 않았습니다.

## 2. 사용자와 기획 판단
| 선택 | 이유 | 남는 한계 |
|---|---|---|
| 텍스트·공개 링크의 한 흐름 우선 | 저장부터 결과물까지 재현 가능하게 만들기 | 모든 입력 형식 이해는 미완성 |
| 내 생각은 사람이 작성 | 원문·사용자 의견·AI 해석 혼동 방지 | 직접 입력 수고 |
| 기획자·마케터·연구자·일상 기록자 관점 | 직업을 고정하지 않고 질문의 초점 선택 | 사용자 상황은 별도 입력 없으면 알 수 없음 |
| 단어 검색과 주제 연결 | 적은 기록에서도 동작을 설명하기 쉬움 | 의미 검색·자동 지식 그래프 아님 |
| 기본 초안 + 선택적 Gemini | 연결·한도 실패에도 편집·저장 유지 | AI 결과 품질은 검토 필요 |
| 공개 웹 화면 + 기기 내 기록 | 평가자가 접근하면서 개인 기록은 자동 공개하지 않음 | 로그인·기기 간 동기화·서버 백업 없음 |
| 예시·실사용·합성 시험 분리 | 샘플을 성과로 오인하지 않기 위해 | 실제 효과 증거는 별도 수집 필요 |

차별성은 “한국어 제품 사례에 내 관점을 붙여 출처가 연결된 작은 제안으로 옮기는 모바일 흐름”이라는 가설입니다. 2026-10-03의 [수요·경쟁 검토](demand-differentiation-2026-10-03-v01.md)는 탐색 자료이며 경쟁 우위나 지불 의사 검증이 아닙니다. 이번 문서 작업에서 경쟁 기능을 새로 조사한 것은 아닙니다.

## 3. 핵심 흐름
1. 텍스트·공개 링크·이미지·음성 중 기록 형식을 고릅니다. 링크는 주소를 먼저 보존하고 본문을 읽으며, 유튜브는 공개 자막을 우선 요청합니다.
2. 읽지 못하면 원문 다시 읽기 또는 직접 붙여넣기로 본문을 확보합니다.
3. 선택적으로 내 생각을 남기거나 AI 도우미를 사용합니다.
4. 제목·내 생각·본문 요약·근거·주제 등 기억나는 단어로 다시 찾습니다.
5. 결과물 만들기에서 참고 기록, 종류, 전달 목적, 내 관점을 정합니다.
6. 기본 초안 또는 동의 후 AI 초안을 받고 직접 편집·저장합니다.
7. 창작 메뉴에서 재열기·복사·이미지 내보내기를 합니다.
8. 실제로 사용했다면 사용 여부와 근거를 직접 남깁니다. 저장·복사·다운로드는 실제 활용과 다릅니다.

내 생각·AI 사용은 필수가 아닙니다. 본문 확보 실패가 주소·기존 생각·결과물 저장을 막지 않도록 합니다.

## 4. 현재 구현 범위
| 영역 | 구현 | 완료 조건·제약 |
|---|---|---|
| 수집 | 텍스트, 공개 링크 본문, 이미지 문자 인식·음성 인식 지원 경로, 유튜브 공개 자막 | 로그인·유료 글, 자막 없는 영상, 모든 이미지·음성 처리 성공 보장 없음 |
| 원문 다시 보기 | 기사·영상·글은 원문 링크, 음성은 다시 듣기, 이미지는 원본 열기 | 외부 원문이 삭제되거나 접근을 막으면 열리지 않을 수 있음 |
| 내 생각 | 기록과 별도 작성·수정 | 원문 사실로 표시하지 않음 |
| 탐색 | 저장 날짜·시각 최신순, 검색·주제·달력 | 이전 날짜만 있는 기록은 동일 날짜의 기존 순서 유지 |
| 함께 보는 기록 | 주제·단어 등 기존 연결 규칙에 따른 추천 | 기록 수만으로 무조건 묶지 않음, 의미 유사도 AI 아님 |
| 사용법 예시 | 별도 사용법 안내에서 예시 흐름 확인 | 자동 추천·실시간 AI 생성·사용자 성과가 아님 |
| 기록 AI | 본문·관점·선택 맥락으로 구조화된 요약·질문·적용 제안 | 원문 확보·최종 전송 동의 필요 |
| 창작 | AI 왕복 없이 즉시 만드는 편집 가능 초안, 이후 선택형 AI 표현 제안, 게시물·스토리·브런치·제안서·프로젝트 형식, 저장·재열기 | 게시 전 완성도·사실 정확성 사용자 검토 필요 |
| 공유 | 복사, 게시물 1080×1350·스토리 1080×1920 PNG, 지원 환경 공유 메뉴 | 인스타그램 자동 게시 없음, 긴 글 전체를 카드에 담지 못할 수 있음 |
| 공유 전 안내 | 길이·출처·관점 보조 점검 | 강제 승인·정확성 인증이 아님 |
| 분석 | 이 기기의 입력·재열람·생각·결과물·도움 평가·활용 근거 | 전체 고객 분석·서버 관리자 통계 아님 |
| 사용 테스트 | 과제 타이머·막힘·전후 회차 연결·JSON/CSV | 도구 존재와 실사용 효과 입증은 별개 |
| 삭제·보존 | 모든 기록과 임시 작업 삭제, 기기 저장·이전 상태 보관·검사 후 백업 합치기 | 삭제한 항목은 현재 브라우저에서 복구되지 않으며, 브라우저 데이터 삭제·기기 교체 위험과 서버 동기화 부재 |
| 입력 초기화 | 저장 실패 때 입력 보존, 링크·텍스트 저장 성공 뒤 입력창과 선택 상태 초기화 | 주소별 브라우저 저장 공간은 서로 공유되지 않음 |
| 알림·설치 | 지원 브라우저의 설치·공유 대상·알림 설정 | 모든 모바일 환경·백그라운드 예약 푸시 보장 없음 |

기본 5개와 제품 사례 3개는 사용법 예시이며 실제 사용 집계에서 제외합니다. 예시만 참고한 결과물도 실제 활용 성과로 세지 않습니다.

## 5. AI 본문·동의·맥락 요구사항
순서: **본문 준비 → 필요한 맥락 선택 → 실제 전송 내용 확인·동의 → AI로 정리하기**.

| 조건 | 동작·수용 기준 |
|---|---|
| 본문 없음 | “본문이 있어야 AI 정리를 실행할 수 있어요”와 불러오기·붙여넣기 제공. 링크만으로 추측하지 않음 |
| 본문 80자 미만 | 분량 안내, AI 요청하지 않음 |
| 본문 24,000자 초과 | 원본 보존, 원문과 일치하는 연속 부분 80~24,000자 선택 |
| 선택 맥락 | 저장한 생각, 현재 고민, 원하는 결과물 각각 기본 미선택. 선택한 비어 있지 않은 항목만 전송 |
| 항목 분량 | 맥락 항목별 최대 1,000자. 긴 생각은 전송할 부분을 현재 고민에 직접 정리 |
| 필수 전송 | 제목·선택 본문·관점. 선택 맥락을 포함한 전송 내용을 미리보기 |
| 동의 변경 | 본문·제목·관점·선택 맥락 변경 시 기존 동의 해제 |
| 응답 지연 | 요청 이후 원문·선택 본문·맥락이 바뀌면 이전 응답 적용하지 않음 |
| 실패 | 시간 초과·한도·형식·근거 검사 실패를 안내하고 기존 기록 보존 |

개인 맥락이 없으면 일반 적용 예시임을 표시하고 필요한 질문을 제시합니다. 직장·경험·감정·목표·사용자 의견을 AI가 대신 만들어내도록 하지 않습니다. 입력 본문 안의 명령은 지시가 아닌 분석 자료로 취급합니다.

## 6. AI 답변 구조와 신뢰성
기본 순서는 **자료 정보 → 핵심 요약 → 주요 근거 → 해석과 한계 → 나에게 남길 질문 → 다시 쓸 방법**입니다. 주요 근거는 꼭 세 개로 고정하지 않고, 자료를 이해하는 데 필요한 만큼만 제시합니다.

| 구분 | 내용 |
|---|---|
| 자료 정보 | 제목·형식·출처와 다시 찾을 검색어·활용 상황 |
| 핵심 요약 | 원문을 읽기 쉬운 문장으로 간결하게 정리 |
| 주요 근거 | 원문에서 확인되는 사실·작성자의 주장을 근거 위치와 함께 필요한 수만큼 제시 |
| 해석과 한계 | AI의 해석을 원문과 분리하고, 자료로 확인하지 못한 점을 명시 |
| 나에게 남길 질문 | 사용자의 경험·생각을 임의로 만들지 않고 질문으로 남김 |
| 다시 쓸 방법 | 새로운 창작 제안을 사실이나 사용자 의견처럼 섞지 않고 별도 제시 |

인용이 본문에 포함되는지와 사실 항목의 숫자 문자열이 본문에 존재하는지 검사합니다. 불일치 시 응답을 적용하지 않습니다. **인용 존재·숫자 존재는 의미상 뒷받침, 인과관계, 모든 해석의 정확성을 증명하지 않습니다.** 요약·해석·행동 제안 전체를 자동 사실 검증하는 기능은 없습니다. 없는 목표 수치·성과·사용자 생각을 만들지 않는 것은 생성 지시와 검토 원칙이며 오류 0% 보장이 아닙니다.

창작 AI는 선택한 기록의 요약·핵심 문장·내 생각·목적·관점·기존 초안을 전송하기 전 별도 동의를 받습니다. 추가 선택 시 기록별 본문 앞 6,000자를 포함합니다. 기록 AI의 세 가지 맥락 선택과 창작 AI의 전송 범위는 동일하지 않습니다. 창작은 제목·본문 형식이며 기록 AI와 같은 인용 검사를 모두 적용하지 않습니다. 원문/사용자 의견/제안을 구분하도록 지시하지만 사용자가 검토해야 합니다.

## 7. 기술·보안·운영
- 정적 HTML·CSS·JavaScript와 브라우저 저장으로 핵심 기능 작동. 공개 GitHub는 화면 파일을 memoive/에, Sites 작업본은 dist/에 보관합니다. 운영 Sites 버전 54와 Vercel 공개 복제본은 같은 화면 코드를 사용합니다.
- 사이트는 현재 공개입니다. 주소에 private가 남아 있어도 접근 권한의 뜻은 아닙니다. 접속만으로 제작자의 브라우저 기록이 공유되지는 않습니다. 공용 기기 사용에는 주의해야 합니다.
- 공개 링크 읽기는 외부 원문 변환 서비스에 URL을 보냅니다. 사진 표시는 원문 이미지 서버에도 요청합니다. 이 단계 자체는 Gemini 전송이 아닙니다.
- Gemini 요청은 Cloudflare Workers를 통합니다. 비밀 인증값은 서버에 두고 브라우저·GitHub에 넣지 않습니다.
- 2026-10-05 운영 연결에서 Gemini 응답과 /health의 ready=true, insightProtocol=2를 확인했습니다. 당시 설정 모델은 gemini-3.5-flash-lite입니다. 다른 프로젝트에서의 이용 가능 모델·무료 한도는 별도 확인해야 합니다.
- 서버는 허용 Origin, JSON 형식, 요청 크기 100,000바이트, 활성화 설정, 사용량 제한을 검사합니다. 제한 바인딩 누락 시 닫힘 방식으로 요청을 거절합니다.
- Worker의 5회/60초는 지역 단위 요청 제한이며 Google의 무료 일일 요청 수가 아닙니다. 전 세계 총량·일일 예산·요금 상한이 아닙니다.
- Origin 검사는 사용자 로그인 인증이 아닙니다. 개인별 할당·강한 공개 남용 방지·전체 예산 차단은 남은 운영 과제입니다.
- Gemini 무료 등급으로 보낸 자료가 공급자 제품 개선에 사용될 수 있음을 전송 화면에 안내합니다. 개인정보·비공개 자료 전송을 피합니다.
- AI 서버 코드는 요청 본문·생성 결과를 별도로 저장하거나 로그로 쓰지 않습니다. 공급자 데이터 처리 정책과 Cloudflare 기본 운영 로그까지 없다는 의미는 아닙니다.
- 운영 Worker는 기본적으로 운영 Site Origin만 허용하므로 로컬 미리보기에서 실 AI를 호출하면 거절될 수 있습니다. 기본 초안과 합성 자동 검사는 API 키 없이 가능합니다.
- 서비스 워커 캐시는 일부 오프라인 화면을 지원하지만 외부 원문·AI 기능의 오프라인 실행을 보장하지 않습니다.

## 8. 저장·모바일 수용 기준
기존 기록·생각·결과물·백업 형식을 보존합니다. 저장 용량 오류, 접근 차단, 손상본, 다른 탭 변경 감지, 잘못된 백업, 같은 ID 결과물 충돌을 검사합니다. 완전히 동시적인 여러 탭의 원자적 저장이나 서버 영구 보관은 보장하지 않습니다.

백업 10MB 검사, 최근 사건 2,000개 제한, 앱/사용 테스트 별도 백업은 유지합니다. 긴 기록과 500개 초과 결과물을 조용히 잘라내지 않습니다.

스크롤 막대는 숨기되 휠·터치·키보드와 긴 내용 접근을 유지합니다. 모바일 글자·터치 영역·창 포커스·닫기 시 작성물 보호를 유지합니다. 375px 브라우저 검증은 실물 휴대폰·음성 인식·공유 메뉴·보조 기술 전수 검증이 아닙니다.

# MEMOIVE 서비스 기획·데이터 활용 고도화 v31

## 이번에 해결한 것
기능 개수를 늘리는 대신 문제 가설 → 관찰 → 개선 결정 → 제작자 전후 시험을 연결했다. 기존 내 사용 테스트와 개인 분석 화면을 보존했다. 대상 사용자 수요와 실제 활용 효과는 기능 배포로 확보되는 것이 아니며 아직 사용자 조사·사용 기록이 필요하다.

| 필요한 증거 | 구현된 수집·정리 기능 | 아직 주장할 수 없는 것 |
|---|---|---|
| 대상 사용자의 문제 중요도 | 대상·상황·가설·주 지표·판정 기준·보호 조건, 직접 사용/인터뷰/행동 관찰 구분, 실제 행동과 해석 및 기존 대안·반례 기록 | 고객 대표성, 실제 수요 확정 |

## 저장과 개인정보
- 현재 서비스와 동일한 기기 한정 방식. 기획 근거는 `memoive-evidence-v1`, 기존 시간 측정은 `memoive-self-study-v1`로 분리한다. 원문·앱 기록을 이 기능에서 자동 수집하지 않는다.
- 가설·관찰·결정은 추가 방식이다. 가져오기 시 같은 ID의 기존 기록을 우선하여 덮어쓰지 않는다. 참조가 깨진 백업은 가져오지 않는다.
- 읽기 실패·다른 탭 변경·저장 공간 실패 시 입력과 원본을 보존하고 안내한다. 기획 근거 백업과 테스트 백업은 별도이므로 둘 다 보관해야 한다.
- 외부 참여자 이름·연락처 대신 익명 코드를 사용한다. 관찰 메모는 작성자 기록이지 인증된 사용자 조사가 아니다. AI와 분석 서버로 전송하지 않는다.
- 포트폴리오 기록은 미리 보기를 거친 뒤 사용자가 파일로 내려받는다. 자동 공개나 GitHub 업로드는 없다.

## 최소 검증 절차
1. 하나의 대상 상황과 문제를 정하고 관찰 전에 판정 기준을 남긴다. 확정된 수요로 표현하지 않는다.
2. 기존 방식과 MEMOIVE를 각각 사용하되 성공뿐 아니라 실패·도움·중단을 기록한다.
3. 실제 막힌 행동과 원인 해석을 구분한다. 가설에 반하는 관찰도 남긴다.
4. 관찰 근거를 연결하여 작은 개선을 선택하고 대안·선택 이유·적용 버전을 기록한다.
5. 유사한 난이도의 새로운 자료를 같은 조건 코드로 묶어 재시험한다. 반복 학습·기기 차이·자료 난이도 차이를 보고한다.
6. 비교 가능한 두 시험의 시간 차이도 인과 효과로 주장하지 않는다. 제작자 반복 사용은 1명이며 대상 사용자 검증을 대체하지 않는다.

# MEMOIVE 제품 요구사항 정의서 v2.0

작성일: 2026-10-14 · 문서 v2.0 · 2026-10-14 운영 배포 (배포 기록은 10.5)

이전 문서: [PRD v1.3 (2026-10-06)](PRD_MEMOIVE_2026-10-06-v01.md). v1.3은 **현재 구현 범위·AI 동의·저장 안정성의 기준**으로 그대로 유효합니다. v2.0은 그 위에서 **외부 피드백을 근거로 문제 정의·핵심 루프·지표·다음 개발 우선순위**를 다시 정한 문서입니다. 두 문서가 충돌하면 제품 방향과 우선순위는 v2.0, 이미 구현된 동작의 세부 기준은 v1.3을 따릅니다.

## 0. 변경 요약 (v1.3 → v2.0)

| 구분 | v1.3 | v2.0 |
|---|---|---|
| 한 줄 정의 | 흘러가는 정보를 영감으로, 영감을 결과물로 | **쌓아 둔 기록이 나에게 다시 돌아오는 서비스** |
| 문제의 초점 | 저장 이후 의미를 잊어 결과물에 쓰기 어렵다 | 저장 이후 **다시 보지 않는다** → 생각이 쌓이지 않는다 → 결과물로도 이어지지 않는다 |
| 핵심 루프 | 기록 → 내 생각 → 다시 찾기 → 글쓰기 | 기록 → **AI 질문으로 생각 끌어내기** → **다시 돌아오기(리마인드·회고)** → 원칙·글로 쓰기 |
| AI의 역할 | 요약·해석, 초안 표현 제안 | 요약·해석 + **질문하는 AI, 쓴 뒤 피드백하는 AI**. 대신 써주는 AI는 보조로 낮춤 |
| 북극성 지표 | 결과물 전환 비율 | **다시 돌아와 생각을 덧붙인 기록 비율** |
| 근거 | 제작자 맥락, 합성 시험 | 제작자 맥락 + **발표 시연 후 외부 서면 피드백 16건** |
| 다음 우선순위 | 제작자 반복 사용 검증 | P1 신뢰·생각 작성 강화 → P2 회고·원칙 루프 |

## 1. 외부 피드백과 해석

### 1.1 수집 개요
- 형태: 서비스 발표·시연 직후 참여자가 남긴 서면 의견 16건 (같은 사람의 중복 없음)
- 성격: **시연을 본 첫 반응**입니다. 직접 사용한 뒤의 평가나 사용 데이터가 아니며, 수요·지불 의사·유지율을 입증하지 않습니다.
- 활용: 문제 공감 여부와 기능 기대를 확인하는 정성 자료로만 사용합니다. 각 개선은 2026-10 이후 사용 검증으로 다시 확인합니다(9장).

### 1.2 분류

| 묶음 | 인원 | 요지 | 현재 구현 | v2.0 판단 |
|---|---|---|---|---|
| A. 저장만 하고 다시 안 본다 | 5 | 스크랩한 자료를 다시 안 보게 된다, 그 부분을 파고들어 흥미롭다 | 문제 정의에 반영됨 | **문제 공감은 가장 강함.** 북극성 지표를 이 문제에 맞춤 |
| B. 관점 직접 입력·관점별 템플릿 | 4 | 카테고리 밖 관점 입력, 관점별 템플릿, 관점별 비교 | 관점 4개 고정, 관점별로 바뀌는 것은 질문 한 줄 | P1 ② |
| C. 질문으로 생각 구체화, 쓴 뒤 피드백 | 3 | AI가 질문해 생각을 구체화, AI 글 제안보다 작성 후 피드백 | "나에게 남길 질문"을 일방향으로 표시 | P1 ③ |
| D. 기록 이후 무엇을 하나 | 3 | 단순 기록 이후의 쓰임, 월간 분석과 편중, 기록으로 원칙 만들기, 필요한 지식 요약 | 행동 지표 위주의 분석 화면 | P2 ④⑤ |
| E. 추천 이유 불분명 | 1 | 이어지는 글이 왜 추천되는지 모르겠다 | 공통 주제·단어 1개를 짧은 문구로 표시 | P1 ① (영향 대비 비용이 작음) |
| F. 리마인드 | 1 | 갤러리 "추억"처럼 예전 기록을 다시 보여주고 지금과 비교 | **이미 있음** (다시 보기 날짜·알림 주기) | P2 ⑥ + 발견성 |
| G. 모바일 | 3 | 떠오를 때 바로 기록, 앱으로 쓰고 싶다 | **이미 있음** (PWA 설치, 공유 대상) | 발견성. 네이티브 앱은 범위 밖 |
| H. 영상 요약 | 1 | 영상을 다시 보기 귀찮다 | **이미 있음** (공개 자막 기반 요약) | 발견성 |
| 기타 | 2 | 범용 확장 시 작업 시간 단축(1), 관심 영상 추천(1) | - | 범용 확장은 관점 커스터마이징으로 흡수, 영상 추천은 보류(8장) |
| 질문 | 2 | AI 정리 프롬프트 방식, 자막 수집 방식 | - | 기능 요청이 아니므로 답변으로 처리 |

### 1.3 핵심 해석
1. **문제 공감은 "글쓰기"보다 "다시 안 봄"에 몰려 있다.** v1.3은 결과물 전환을 성공 기준으로 두었지만, 사람들이 공감한 고통은 그보다 앞 단계입니다. 결과물은 기록이 다시 돌아온 뒤에야 생깁니다.
2. **F·G·H는 기능이 없어서가 아니라 보이지 않아서 나온 요청이다.** 기능을 더 만들기보다 처음 쓰는 사람이 이 기능을 만나는 시점을 설계하는 일이 먼저입니다.
3. **AI가 대신 쓰는 것에 대한 기대는 낮고, 질문·피드백에 대한 기대는 높다.** v1.3의 원칙인 "내 생각은 사람이 작성"과도 일치합니다. AI의 역할을 생성에서 질문·피드백으로 옮깁니다.
4. **"기록 이후 무엇을 하나"가 제품의 가장 큰 열린 질문이다.** v2.0의 답은 "쌓인 생각을 원칙으로 묶는다"입니다(P2 ⑤).

## 2. 제품 정의와 문제

**쌓아 둔 기록이 나에게 다시 돌아오는 서비스.**

MEMOIVE는 저장한 자료에 내 생각을 붙이고, 그 기록이 시간이 지난 뒤 다시 나에게 돌아오게 해, 생각을 원칙·글·기획안으로 이어 쓰게 하는 개인 기록 서비스입니다.

### 문제 가설
- 1차 문제: 자료를 저장한 뒤 **다시 보지 않는다.** (외부 피드백 5건 공감)
- 2차 문제: 저장할 때 생각을 남기지 않거나, 남겨도 막연해서 나중에 쓸모가 없다. 글쓰기 자체가 어렵다.
- 3차 문제: 다시 보더라도 기록들이 서로 연결되지 않아 결과물로 이어지지 않는다.

### 대상 사용자
| 구분 | 설명 |
|---|---|
| 초기 사용자 (유지) | 제품 사례를 모아 기획안·포트폴리오를 쓰는 PM/PO·서비스 기획·컨설팅 직무 준비자 |
| 확장 사용자 (v2.0 추가) | 직무 밖 관심사(과학, 삶, 취미)를 기록하고 싶은 사람. 관점 커스터마이징으로 수용 |

대상 사용자의 대표 수요는 아직 인터뷰로 검증되지 않았습니다. 피드백 참여자가 대상 사용자와 얼마나 겹치는지도 확인하지 않았습니다.

## 3. 핵심 루프 v2

```
저장 ──▶ 생각 끌어내기 ──▶ 다시 돌아오기 ──▶ 쓰기
 │        (AI 질문 1~2개)     (리마인드·회고)     (원칙·글·기획안)
 │                                │                    │
 └────────── 연관 기록 추천(이유와 함께) ◀──────────────┘
```

| 단계 | 사용자가 하는 일 | v2.0에서 바뀌는 점 |
|---|---|---|
| 저장 | 링크·영상·텍스트를 기록 | 내 관점(직접 입력 가능)과 그 관점의 템플릿을 고름 |
| 생각 끌어내기 | 질문에 답하며 생각을 남김 | AI가 질문하고, **답한 내용이 그대로 "내 생각"이 됨** |
| 다시 돌아오기 | 예전 기록과 지금 생각을 비교 | 리마인드를 "생각 비교"로 바꾸고, 월간 회고 리포트 제공 |
| 쓰기 | 여러 기록의 생각을 묶어 결과물로 | "나의 원칙" 형식 추가, AI는 작성 후 피드백 중심 |
| 연결 | 관련 기록을 따라 이동 | 추천 이유를 겹친 단어와 내 생각 구절로 구체적으로 표시 |

## 4. 지표 체계

### 4.1 북극성 지표
**다시 돌아와 생각을 덧붙인 기록 비율** = 저장한 날과 다른 날에 생각을 추가·수정한 고유 기록 수 ÷ 예시를 제외한 기록 수

- 선택 이유: "다시 안 봄"(1차 문제)과 "생각이 쌓이지 않음"(2차 문제)을 함께 반영합니다. 단순 재열람은 우연한 클릭도 세지만, 생각 덧붙이기는 실제로 다시 생각했다는 행동입니다.
- 주의: 기기 내 이벤트로 계산하는 자기 기록 지표입니다. 고객 전체 유지율이 아닙니다. 이벤트 보관 한도(최근 2,000개)를 넘은 과거 행동은 빠질 수 있습니다.

### 4.2 보조 지표

| 지표 | 정의 | 연결된 기능 |
|---|---|---|
| 생각 작성 비율 | 생각이 있는 기록 ÷ 예시 제외 기록 (v1.3 유지) | P1 ③ |
| 질문 응답률 | AI 질문에 하나 이상 답한 기록 ÷ 질문을 받은 기록 | P1 ③ |
| 생각 길이 중앙값 | 기록별 내 생각 글자 수의 중앙값. 품질 지표가 아니라 구체화의 보조 신호 | P1 ③ |
| 추천 클릭률 | 연관 기록 클릭 수 ÷ 연관 기록 노출 수 | P1 ① |
| 사용자 정의 관점 사용률 | 직접 만든 관점으로 저장한 기록 ÷ 전체 기록 | P1 ② |
| 리마인드 반응률 | 리마인드에서 기록을 열거나 생각을 덧붙인 수 ÷ 리마인드 노출 수 | P2 ⑥ |
| 원칙 생성 수 | 2개 이상의 기록을 근거로 연결한 "나의 원칙" 결과물 수 | P2 ⑤ |
| 결과물 전환 비율 | 결과물에 연결된 고유 기록 ÷ 예시 제외 기록 (v1.3 유지, 후행 지표로 이동) | 전체 |

### 4.3 가드레일
- 기록 유실·출처 오연결 0건 유지 (v1.3 저장 수용 기준)
- AI 전송 전 동의 화면을 건너뛴 전송 0건
- AI가 사용자의 경험·생각을 지어내 "내 생각"에 넣은 사례 0건 (사용자 확인 없이 저장되지 않음)

## 6. 기능 요구사항

### P1 ① 추천 이유 구체화

**배경:** 연관 기록은 공통 주제(가중치 4)와 공통 단어(가중치 1)로 최대 3개를 고르고, 이유로 "‘주제’ 주제가 이어져요" 또는 "‘단어’ 생각이 반복돼요" 한 문장만 보여줍니다. 무엇이 어떻게 이어지는지 알 수 없습니다.

**사용자 이야기:** 기록을 읽다가 연관 기록을 볼 때, 왜 이 기록이 나왔는지 바로 알아서 열어볼지 판단하고 싶다.

**요구사항**
1. 추천마다 **겹친 근거를 종류별로** 보여줍니다: 공통 주제, 공통 단어(최대 3개), 두 기록의 내 생각에서 공통 단어가 들어 있는 구절.
2. 내 생각끼리 겹친 경우를 가장 먼저 보여줍니다. 예: `두 기록 모두 생각에 ‘작은 실험’을 남겼어요 — “먼저 작게 시험해보자”`
3. 근거 단어는 기록 본문에서 강조 표시합니다.
4. 이유를 만들 수 없는 추천은 보여주지 않습니다.
5. 의미 기반 유사도처럼 보이는 표현(예: "비슷한 내용")을 쓰지 않습니다. 현재 방식은 단어·주제 일치입니다.

**수용 기준**
- 모든 추천 항목에 근거 종류가 1개 이상 표시된다.
- 내 생각에서 겹친 경우 해당 구절이 원문 그대로(최대 40자) 표시된다.
- 예시 기록끼리만 연결된 추천도 예시임을 표시한다.

**가설:** 이유가 구체적이면 추천 클릭률이 오른다.

### P1 ② 관점 커스터마이징 + 관점별 템플릿

**배경:** 관점은 기획자·마케터·연구자·일상 기록자 4개로 고정되어 있고, 관점에 따라 달라지는 것은 질문 문구 하나입니다. 4명이 관점 직접 입력이나 관점별 템플릿을 요청했습니다.

**사용자 이야기:** 내 상황에 맞는 관점(예: UX 리서처, 창업 준비, 과학 공부)으로 기록하고, 관점에 맞는 틀을 따라 생각을 정리하고 싶다.

**요구사항**
1. 기본 관점 4개는 유지하고, 사용자가 관점을 추가·이름 변경·삭제할 수 있습니다. (최대 10개, 이름 최대 20자)
2. 각 관점은 **템플릿**을 가집니다. 템플릿은 생각 입력란의 소제목 2~4개입니다.

   | 관점 | 기본 템플릿 |
   |---|---|
   | 기획자 | 문제는 무엇인가 / 내 가설 / 내가 해볼 작은 실험 |
   | 마케터 | 누구에게 / 어떤 메시지로 / 어느 채널에서 |
   | 연구자 | 주장 / 근거의 강도 / 더 확인할 것 |
   | 일상 기록자 | 느낀 점 / 내일 해볼 것 |
   | 사용자 정의 | 사용자가 소제목을 직접 작성. 비우면 자유 입력 |

3. 템플릿 소제목은 입력 안내일 뿐이며 모두 비워도 저장됩니다.
4. 같은 기록에 다른 관점의 생각을 추가할 수 있고, 기록 상세에서 관점별 생각을 나란히 봅니다(관점 비교).
5. AI 요약·질문 요청 시 사용자 정의 관점의 이름과 템플릿 소제목을 관점 정보로 전송합니다. 동의 화면에 표시합니다.
6. 기존 기록의 관점·생각 데이터는 변환 없이 그대로 열려야 합니다. 기존 `thought` 문자열은 해당 관점의 자유 입력으로 취급합니다.

**수용 기준**
- 사용자 정의 관점으로 저장·검색·백업·복원·동기화가 된다.
- 관점을 삭제해도 그 관점으로 쓴 생각은 지워지지 않고 "삭제된 관점"으로 남는다.
- 기존 백업 파일을 복원해도 기록이 손상되지 않는다.

**가설:** 관점과 템플릿이 내 상황에 맞으면 생각 작성 비율과 생각 길이가 늘어난다.

### P1 ③ AI 질문으로 생각 끌어내기

**배경:** "나에게 남길 질문"은 AI 정리 결과에 함께 나오지만 답할 곳이 없습니다. 생각을 구체화하도록 AI가 질문해 달라는 요청과 글쓰기가 어렵다는 의견이 있었습니다.

**원칙:** AI는 질문하고, 답은 사람이 씁니다. AI는 사용자의 경험·감정·의견을 만들어내지 않습니다(v1.3 5장 유지).

**사용자 이야기:** 자료를 저장한 직후, 질문 한두 개에 답하는 것만으로 나중에 다시 쓸 수 있는 생각을 남기고 싶다.

**요구사항**
1. 기록을 저장한 뒤 또는 기록 상세에서 "질문 받기"를 누르면 질문 1개를 받습니다. 답한 뒤 "한 번 더"로 최대 3개까지 이어 받습니다.
2. 질문은 선택한 관점과 템플릿을 따릅니다. 예: 기획자 → "이 사례의 제약 조건 중 내 프로젝트에도 있는 것은?"
3. 두 번째 질문부터는 직전 답을 바탕으로 더 구체적으로 묻습니다(예: 막연한 답에는 사례나 숫자를 묻기).
4. 답은 입력하는 대로 **"내 생각"의 해당 질문 아래에 저장**됩니다. 질문과 답은 함께 보관합니다.
5. AI 연결이 없거나 동의하지 않은 경우 관점 템플릿의 기본 질문을 대신 보여줍니다(오프라인 동작).
6. 전송 범위: 제목, 선택한 본문, 관점, 이전 질문과 사용자가 쓴 답. 첫 요청 전에 v1.3의 미리보기·동의 절차를 따르고, 같은 기록에서 이어지는 질문은 범위가 바뀌지 않는 한 다시 묻지 않습니다.
7. 질문에 답하지 않고 닫아도 기록은 그대로 저장됩니다.

**창작 단계 AI 역할 변경 (같은 원칙의 확장)**
- 결과물 화면의 기본 AI 기능을 "표현 제안"에서 **"쓴 글 피드백"**으로 바꿉니다. 피드백 항목: 주장이 분명한가, 근거 기록과 연결되는가, 내 생각과 출처 내용이 구분되는가, 빠진 반론.
- 피드백은 글을 직접 고치지 않고 의견으로만 표시합니다. 기존 표현 제안은 보조 기능으로 남깁니다.

**수용 기준**
- AI가 만든 문장이 사용자 입력 없이 "내 생각"에 저장되지 않는다.
- AI 실패 시에도 기본 질문으로 같은 흐름을 끝까지 진행할 수 있다.
- 질문·답 기록이 백업·동기화에 포함된다.

**가설:** 저장 직후 질문을 받으면 생각 작성 비율과 생각 길이가 늘어나고, 그 기록은 나중에 다시 쓰일 가능성이 높아진다.

### P1 공통: 기존 기능 발견성 개선

**배경:** 리마인드, 모바일 설치·공유 저장, 영상 자막 요약은 이미 있지만 피드백 5건이 "있으면 좋겠다"고 요청했습니다.

**요구사항**
1. 첫 기록을 저장한 직후, 다시 보기 알림(리마인드)을 켤지 묻습니다. 기본값과 주기는 기존 설정을 따릅니다.
2. 모바일 브라우저에서 두 번째 방문부터 홈 화면 추가와 "공유하기 → MEMOIVE"로 저장하는 방법을 한 번 안내합니다.
3. 유튜브 주소를 입력하면 저장 전에 "자막으로 요약할 수 있어요"를 표시합니다.
4. 안내는 각각 한 번만 보이고, 설정에서 다시 볼 수 있습니다.

**수용 기준:** 처음 쓰는 사람이 설명 없이 세 기능을 각각 찾을 수 있는지 9장의 과제로 확인합니다.

### P2 ④ 월간 회고 리포트

**사용자 이야기:** 한 달 동안 무엇을 모았는지, 어디에 치우쳤는지, 어떤 생각이 반복됐는지 한눈에 보고 싶다.

**요구사항**
1. 매월 1일(또는 사용자가 열 때) 지난달 리포트를 만듭니다.
2. 기기에서 계산하는 항목: 기록 수, 주제·관점·형식별 분포, 생각을 남긴 비율, 다시 돌아온 기록, 가장 많이 연결된 기록.
3. 편중 안내: 한 주제가 60% 이상이면 "이번 달은 ‘PM 사례’에 집중했어요. 다른 관점의 기록도 남겨볼까요?"처럼 표시합니다. 판단이나 강요가 아니라 안내입니다.
4. 선택형 AI 요약(동의 후): 내 생각들에서 반복된 생각 3개, 다음 달에 더 알아볼 지식·스킬 제안. 근거 기록을 함께 표시합니다.
5. 리포트는 저장되고 다시 열 수 있으며, 리포트에서 바로 "나의 원칙"(⑤)을 만들 수 있습니다.

**수용 기준:** 기록이 5개 미만인 달은 분포 대신 "기록이 더 모이면 보여드려요"를 표시한다. 예시 기록은 집계에서 제외한다.

### P2 ⑤ "나의 원칙" 결과물 형식

**배경:** "이런 콘텐츠의 핵심은 쌓아서 이후에 써보는 것, 저는 원칙을 만드는 데 활용한다"는 피드백. "기록 이후 무엇을 하나"에 대한 MEMOIVE의 답입니다.

**사용자 이야기:** 여러 기록에서 반복해서 남긴 생각을 내가 일할 때 쓰는 원칙 한 문장으로 정리하고, 그 원칙이 어디서 왔는지 언제든 확인하고 싶다.

**요구사항**
1. 결과물 형식에 "나의 원칙"을 추가합니다. 구성: 원칙 한 문장, 왜 그렇게 생각하는지, 근거 기록(2개 이상), 적용해 본 경험(선택).
2. 원칙 문장은 사용자가 씁니다. AI는 선택한 기록의 내 생각에서 공통점을 질문 형태로 제안할 수만 있습니다.
3. 원칙 목록 화면을 따로 둡니다. 원칙마다 근거 기록 수와 마지막으로 고친 날짜를 보여줍니다.
4. 새 기록을 저장할 때 기존 원칙과 공통 단어가 있으면 "이 기록이 ‘○○’ 원칙과 이어져요"를 표시하고, 근거로 추가할 수 있게 합니다.
5. 원칙은 수정 이력을 남겨 생각이 바뀐 과정을 볼 수 있습니다.

**수용 기준:** 근거 기록이 2개 미만이면 원칙으로 저장하지 않고 초안으로 둔다. 근거 기록을 삭제해도 원칙은 남고, 삭제된 근거가 표시된다.

### P2 ⑥ 리마인드를 생각 비교로 확장

**사용자 이야기:** 예전에 남긴 생각을 다시 보고, 지금의 생각을 덧붙여 생각이 어떻게 바뀌었는지 보고 싶다.

**요구사항**
1. 홈 화면에 "○개월 전 오늘의 생각" 카드를 하루 1개 보여줍니다. 대상: 생각이 있는 기록 중 30일·90일·365일 전에 저장한 기록, 없으면 다시 보기 날짜가 오늘인 기록.
2. 카드에서 바로 "지금 생각 덧붙이기"를 할 수 있습니다. 덧붙인 생각은 날짜와 함께 이전 생각 아래에 쌓입니다. 이전 생각은 덮어쓰지 않습니다.
3. 기록 상세에 생각의 시간순 흐름을 보여줍니다.
4. "다시 보지 않기"와 "나중에"를 제공합니다.

**데이터 변경:** 현재 `thought`는 문자열 하나입니다. 생각 이력(작성일, 관점, 질문, 내용)의 목록으로 확장하되 기존 문자열은 첫 항목으로 그대로 읽습니다. P1 ②·③과 같은 구조를 함께 씁니다(7장).

**수용 기준:** 생각을 덧붙여도 이전 내용이 바뀌지 않는다. 이 행동이 북극성 지표에 집계된다.

## 7. 데이터 모델 변경

P1 ②·③과 P2 ⑥은 모두 "생각"의 구조를 바꾸므로 한 번에 설계합니다.

| 대상 | 현재 | 변경 |
|---|---|---|
| 관점 | 고정 문자열 4개 (`role`) | 관점 목록: id, 이름, 템플릿 소제목, 기본 여부 |
| 내 생각 | 기록마다 `thought` 문자열 1개 | 생각 항목 목록: 작성일, 관점 id, 질문(선택), 내용, 출처(직접 작성/질문 응답) |
| 결과물 | 게시물·스토리·브런치·제안서·프로젝트 | "원칙" 형식 추가: 원칙 문장, 근거 기록 id 목록, 수정 이력 |
| 회고 리포트 | 없음 | 월, 집계 값, 선택형 AI 요약, 생성일 |

호환 원칙
- 기존 기록·백업·동기화 데이터를 그대로 읽어야 합니다. 변환은 읽을 때 하고 원본 필드는 지우지 않습니다.
- 백업 형식 버전을 올리고, 이전 버전 앱에서 새 백업을 읽을 때 안내합니다.
- v1.3의 저장 수용 기준(용량 오류, 손상본, 다른 탭 변경 감지, 동시 수정 보호)을 새 필드에도 적용합니다.

## 9. 검증 계획

### 9.1 방법
- v1.3의 "내 사용 테스트"(과제 타이머, 막힌 점, 이전·이후 회차 연결)를 그대로 씁니다.
- 각 P1 항목은 **바꾸기 전과 후에 같은 과제**를 수행해 비교합니다. 콘텐츠·기기·학습효과 차이를 함께 적습니다.
- 제작자 반복 사용 뒤, 피드백 참여자 중 희망자 3~5명에게 설명 없이 과제를 주는 외부 검증을 진행합니다. 참여자 수와 조건을 그대로 공개하고 결과를 일반화하지 않습니다.

실행 준비물(배포 전 기준값 측정, 참여자 과제, 모집 메시지, 기록표, 지표 계산)은 [사용 검증 준비물](validation-kit-2026-10-14.md)에 정리했고, `내 사용 테스트` 도구에 v2 과제 5개를 추가했습니다.

### 9.2 과제 예시

| 항목 | 과제 | 성공 기준 |
|---|---|---|
| P1 ① | 기록 상세에서 연관 기록 하나를 고르고 왜 연결됐는지 말하기 | 화면에 보이는 근거로 이유를 설명함 |
| P1 ② | 내 관점을 만들고 그 관점으로 기록 하나 남기기 | 사용자 정의 관점과 템플릿으로 저장 |
| P1 ③ | 새 자료를 저장하고 질문에 답해 생각 남기기 | 답 1개 이상이 내 생각으로 저장됨 |
| 발견성 | 모바일에서 공유로 저장하기, 리마인드 켜기, 영상 요약 받기 | 설명 없이 각각 완료 |
| P2 ⑤ | 기록 2개 이상으로 원칙 하나 만들기 | 근거가 연결된 원칙 저장 |

### 9.3 판단 기준
- 북극성 지표와 보조 지표는 방향만 봅니다. 참여자 수가 적어 통계적 효과로 주장하지 않습니다.
- P1 ③을 써도 생각 작성이 늘지 않으면, P2로 가기 전에 질문 품질과 질문을 띄우는 시점을 먼저 고칩니다.
- 기록 유실이나 출처 오연결은 다른 모든 작업보다 먼저 고칩니다(v1.3 유지).

요구사항과 달라진 점
- **조사 제거 추가:** 구현 중 `실험부터`와 `실험`이 같은 단어로 인식되지 않아 추천이 빠지는 문제를 발견했습니다. 흔한 조사를 떼고 비교하도록 보강했습니다. 형태소 분석은 아닙니다.
- **불용어 보강:** `같은`, `좋겠다`처럼 의미 없는 단어가 추천 근거로 표시되어 기능어를 불용어에 추가했습니다.
- **강조 위치:** 근거 단어는 기록 본문이 아니라 추천 항목의 내 생각 인용 안에서 강조합니다. 추천을 고르는 순간 필요한 정보가 그 자리에 있기 때문입니다.
- **유튜브 안내:** 한 번만 보이는 안내 대신, 유튜브 주소를 입력할 때마다 입력란 아래 상태 문구로 보여줍니다. 입력 맥락에 붙은 안내라 반복돼도 방해가 적다고 판단했습니다.
- **리마인드 안내 조건:** 다시 보기가 이미 켜져 있고 알림 권한도 이미 정해진 경우(허용 또는 차단)에는 안내하지 않습니다.
- **추천 클릭률(4.2):** 처음에는 추천에서 열었는지 구분하는 이벤트가 없었습니다. 2026-10-14 보완에서 `related_opened`(값: 추천을 보던 기록)를 추가했습니다. 노출 수 이벤트는 없어 기록을 연 횟수(`record_opened`)로 근사합니다.
- **측정:** 안내 노출·수락·닫기를 `hint_shown`, `hint_accepted`, `hint_dismissed` 이벤트로 남깁니다. 안내를 이미 본 기록은 브라우저 저장 공간에만 두며 백업에 포함하지 않습니다.

### 10.2 2단계 구현 기록 (2026-10-14)

구현: `frontend/js/perspective-tools.js`(관점 목록·검증), `frontend/js/data-tools.js`(관점별 생각 저장·정규화·병합), `frontend/js/perspective-ui.js`·`frontend/css/perspective.css`(설정·생각 시트·상세 화면), 저장·백업·동기화 연결(`app.js`, `cloud-sync.js`), 검사 `tests/perspective-check.cjs`.

데이터 구조
- 기록에 `thoughts`(관점별 생각 목록)를 추가했습니다. 항목마다 관점 id, 작성 당시 관점 이름, 소제목별 내용, 작성·수정 시각을 둡니다.
- 기존 `thought` 문자열은 지우지 않고, `thoughts`에서 사용자가 쓴 내용만 이어 붙여 자동으로 만듭니다. 템플릿 소제목은 넣지 않습니다. 그래서 검색, 연관 기록, 초안, AI 전송 맥락, 이전 버전 앱이 그대로 동작합니다.
- `thought`만 바꾸는 이전 경로(저장 시 메모, 중복 저장, 이전 버전 기기)에서 늘어난 내용은 "관점 없이 남긴 생각" 항목으로 보존합니다. 같은 항목을 양쪽에서 고친 경우 수정 시각이 늦은 쪽을 따르고, 시각이 없는 이전 기록은 둘 다 남깁니다.

요구사항과 달라진 점
- **AI 전송(요구사항 5) 보류:** 사용자 정의 관점은 만들 때 "가장 가까운 기본 관점"을 고르고, AI 정리에는 그 기본 관점을 보냅니다. 현재 AI 서버가 기본 관점 4개만 허용하기 때문입니다. 관점 이름과 템플릿 전송은 서버를 함께 바꾸는 3단계(P1 ③)에서 구현합니다. 설정 화면에 이 사실을 안내합니다.
- **한 줄 생각 유지:** 생각 시트 맨 위에 기존의 한 줄 입력을 두고, 관점 템플릿은 그 아래의 선택 입력으로 붙였습니다. "한 문장이면 충분하다"는 기존 원칙과 저장 흐름이 길어지는 위험(11장)을 함께 고려했습니다.
- **표시 방식:** 한 줄만 쓴 기록은 이전과 똑같이 보이고(관점 이름만 작게 표시), 템플릿을 채웠거나 관점이 2개 이상일 때 관점별 카드로 보여줍니다. 넓은 화면에서는 2열로 나란히 놓습니다.
- **개수:** 관점 최대 10개는 기본 4개와 내 관점 6개로 구현했습니다. 기본 관점의 템플릿은 고칠 수 없습니다.
- **관점당 생각 하나:** 한 기록에서 같은 관점의 생각은 하나이며 고치면 그 자리에서 바뀝니다. 날짜별로 생각을 덧붙이는 기능은 P2 ⑥에서 다룹니다.
- **기존 생각의 편입:** 관점 없이 남긴 생각만 있는 기록에서 생각을 다듬으면, 그 생각이 선택한 관점의 생각으로 바뀝니다.
- **삭제된 관점:** 삭제된 관점의 생각을 고칠 때도 원래 관점으로 남습니다(새 관점으로 바뀌어 중복되지 않음).
- **백업 형식 버전:** 올리지 않았습니다. 새 필드는 추가만 했고 이전 버전 앱은 새 필드를 무시한 채 `thought`를 읽으므로 호환이 깨지지 않습니다.
- **동기화:** 관점 목록은 덮어쓰지 않고 합칩니다. 이전 버전 앱이 올린 클라우드 데이터가 이 기기의 관점을 지우지 않게 하기 위해서입니다. 대신 다른 기기에서 지운 관점이 다시 나타날 수 있습니다.
- **측정:** `perspective_selected`, `perspective_created`, `perspective_updated`, `perspective_deleted` 이벤트를 남기고, `thought_saved`에 관점(기본 관점 id 또는 `custom`)을 기록합니다. 4.2의 "사용자 정의 관점 사용률"을 이 값으로 계산할 수 있습니다.

확인 범위: 자동 검사(`npm test`)와 375px 브라우저 화면에서 관점 만들기·선택, 템플릿 입력, 관점별 비교 카드, 새로고침 후 유지, 관점 삭제 후 생각 보존, 삭제된 관점의 생각 고치기, 가로 넘침 없음, 콘솔 오류 없음을 확인했습니다. 실제 클라우드 동기화와 여러 기기 사이 병합은 합성 검사로만 확인했습니다.

### 10.3 3단계 구현 기록 (2026-10-14)

구현
- AI 서버: `cloudflare-worker/src/coach.mjs`에 `/v1/question`(질문 하나), `/v1/feedback`(네 가지 의견)을 추가했습니다. 기존 경로와 같은 허용 Origin, 활성화 설정, 요청 제한(같은 제한 키 공유), 요청 크기 상한(60,000바이트)을 적용합니다. `/v1/insight`는 사용자 정의 관점(`perspective`)을 선택적으로 받습니다. 기본 관점(`role`)과 짝이 맞아야 하며, 이 필드가 없는 기존 요청은 그대로 동작합니다. `/health`에 `coaching` 항목을 추가했습니다.
- 화면: `frontend/js/thought-questions.js`(생각 시트의 질문 받기), `frontend/js/writing-feedback.js`(창작 화면의 쓴 글 피드백), 생각 데이터에 질문 출처(`source`) 추가, 검사 `tests/coach-worker-check.mjs`와 기존 검사 보강.

동작
- 기록 상세의 "질문 받기" 또는 생각 시트의 버튼으로 질문을 받습니다. 한 관점에서 최대 3개이며, 앞 질문에 답해야 다음 질문을 받을 수 있습니다.
- AI 질문은 생각 시트에서 동의를 체크했을 때만 요청합니다. 보낼 내용(제목, 자료 앞부분 최대 6,000자, 관점, 내 생각 한 줄, 앞 질문과 내 답 최대 2쌍)을 미리 보여주고, 기록이나 관점을 바꾸면 동의가 풀립니다.
- 동의하지 않았거나 AI 연결이 없거나 요청이 실패하면 관점별 기본 질문을 보여줍니다. 사용자 정의 관점은 자기 템플릿 소제목을 먼저 묻습니다.
- 답은 "내 생각"의 해당 관점 항목에 질문과 함께 저장되고, 답하지 않은 질문은 저장하지 않습니다. 질문 문장은 `thought` 문자열에 넣지 않습니다.
- 창작 화면에 "쓴 글 피드백"을 본문 바로 아래에 두었습니다. 주장, 근거 기록과의 연결, 내 생각과 출처의 구분, 빠진 반론의 네 가지 의견만 받고 글은 바꾸지 않습니다. 기존 표현 제안은 "표현 제안 받기 · 보조"로 이름을 바꿔 남겼습니다.
- 측정: `question_shown`(값 `ai`/`default`), `question_answered`(답한 수), `writing_feedback_received`. 4.2의 질문 응답률을 이 값으로 계산할 수 있습니다.

요구사항과 달라진 점
- 질문 1개마다 "도움 됐어요/아니요" 평가(11장 대응안)는 이번 범위에서 넣지 않았습니다. 응답률로 먼저 확인합니다.
- 저장 직후 질문을 자동으로 띄우지 않고 버튼으로만 엽니다(12장 미결정 사항). 바꾸기 전후 비교로 정합니다.

배포 순서와 주의
1. Cloudflare Worker를 먼저 배포합니다(`cloudflare-worker`에서 `wrangler deploy`). 배포 전에는 질문 요청이 실패해 기본 질문으로 넘어가고, 글 피드백은 "요청 경로를 확인해 주세요" 오류를 보여줍니다.
2. 배포 후 `/health`에서 `coaching: ["question","feedback"]`을 확인합니다.
3. 화면(Vercel 등)을 배포합니다. 사용자 정의 관점이 추가된 AI 정리 요청은 이전 Worker에서도 거절되지 않지만, 관점 이름은 반영되지 않습니다.

확인 범위: 자동 검사(`npm test`, 실제 Gemini 호출 없음)와 375px 브라우저에서 가짜 AI 응답으로 기본 질문, 답하지 않으면 다음 질문 차단, 동의 후 AI 질문, AI 실패 시 기본 질문 전환, 답 저장과 상세 표시, 글 피드백 동의·표시·본문 유지, 가로 넘침 없음, 콘솔 오류 없음을 확인했습니다. 실제 Gemini가 만든 질문과 피드백의 품질은 Worker 배포 후 확인해야 합니다.

### 10.4 P2 구현 기록 (2026-10-14)

진행 순서: 사용자 결정에 따라 4단계(P1 사용 검증)보다 P2 구현을 먼저 진행했습니다. 그래서 P2 순서는 검증 결과가 아니라 PRD에 적은 기본 순서(⑥ → ⑤ → ④)를 따랐습니다.

구현: 계산은 `frontend/js/reflection-tools.js`(화면과 분리해 검사 가능), 화면은 `thought-memory.js`(⑥), `principle-ui.js`(⑤), `monthly-report.js`(④), `frontend/css/reflection.css`. AI 서버에 `/v1/reflection`을 추가했습니다. 원칙(`principles`)과 회고 요약(`reflections`)은 기기 저장, 백업, 동기화에 포함됩니다. 검사는 `tests/reflection-check.cjs`와 `tests/coach-worker-check.mjs`입니다.

⑥ 생각 비교 리마인드
- 홈의 기존 "다시 볼 기록" 카드를 확장했습니다. 30일·90일·365일 전 같은 날 저장하고 생각을 남긴 기록을 먼저 보여주고(간격이 긴 쪽 우선, 하루 1개), 없으면 기존 다시 보기 규칙을 따릅니다. 카드를 하나 더 만들지 않은 것은 비슷한 카드 두 개가 겹치기 때문입니다.
- "지금 생각 덧붙이기"는 오늘 날짜의 덧붙임 항목(`kind: 'followup'`)으로 저장되고, 이전 생각과 관점별 생각은 바뀌지 않습니다. 기록 상세에 "생각의 흐름"을 날짜순으로 보여줍니다.
- "나중에"는 그날만 숨기고(이 브라우저에만 저장), "다시 보지 않기"는 기록에 저장되어 동기화됩니다.
- 북극성 지표 계산 함수(`DataTools.revisitedThought`)를 추가했습니다. 저장한 날보다 뒤의 날짜에 생각을 덧붙였거나 고친 기록을 셉니다(12장의 "다른 날" 기준은 기기 시간 기준 달력 날짜로 정했습니다).
- 측정: `memory_shown`, `memory_snoozed`, `memory_dismissed`, `thought_followup`.

⑤ 나의 원칙
- 창작 화면에 "나의 원칙" 목록과 편집 시트를 두었습니다. 원칙 문장, 이유, 근거 기록, 적용해 본 경험(선택)을 적습니다. 결과물(outputs)과 섞지 않고 별도로 저장해 기존 창작 흐름에 영향을 주지 않게 했습니다.
- 원칙 문장은 사용자가 씁니다. AI 제안 대신, 고른 기록의 내 생각에서 반복된 단어만 힌트로 보여줍니다(요구사항 2의 AI 질문형 제안은 넣지 않음).
- 남아 있는 근거 기록이 2개 미만이면 초안으로 표시합니다. 근거 기록이 삭제되어도 원칙은 남고, 삭제된 근거 수를 보여줍니다.
- 문장을 고치면 이전 문장이 날짜와 함께 이력으로 남습니다.
- 기록 상세에 "이 기록이 근거인 원칙"과, 단어가 겹치는 원칙("이 기록이 ‘○○’ 원칙과 이어져요" + 근거로 추가)을 보여줍니다. 저장 직후 알림이 아니라 기록을 열 때 보여줍니다.
- 측정: `principle_created`(값: 근거 수 또는 `draft`), `principle_updated`, `principle_deleted`, `principle_evidence_added`.

④ 월간 회고
- 분석 화면 맨 위에 두었습니다. 기본은 지난달(기록이 있을 때)이고 달을 고를 수 있습니다. 매월 1일에 알림으로 띄우지는 않습니다.
- 기기에서 계산: 남긴 기록 수, 생각을 남긴 비율, 다시 돌아와 생각을 더한 기록 수, 주제·관점·형식 분포, 가장 많이 이어진 기록, 한 주제가 60% 이상이면 편중 안내. 기록이 5개 미만이면 분포 대신 안내를 보여줍니다. 예시 기록은 제외합니다.
- 선택형 AI 요약: 생각을 남긴 그달 기록(최대 40개)의 제목, 내 생각(500자까지), 주제만 동의 후 보냅니다. 서버는 2개 이상의 기록에 나타난 생각만 주제로 인정하고, 화면은 AI가 고른 번호를 실제로 보낸 기록에 다시 연결합니다. 요약은 달별로 저장되고, 각 주제에서 바로 원칙을 만들 수 있습니다.
- 측정: `reflection_received`.

구현 중 발견해 고친 문제
- 분석 화면이 자기 내용을 다시 그리면서 월간 회고 영역이 문서에서 떨어져 나가, 링크 저장 직후 오류가 났습니다. 그 결과 저장은 되었지만 입력창이 비워지지 않았습니다(기존 브라우저 검사가 발견). 영역이 떨어지면 다시 붙이도록 고쳤습니다. 또 P2 화면 모듈이 실패해도 기록 저장·열기 같은 핵심 흐름은 계속되도록 보호했습니다.
- 첫 화면을 그릴 때 정해진 달이 고정되어 기본값(지난달)이 적용되지 않던 문제를 고쳤습니다.

남은 한계
- 다른 기기에서 지운 원칙은 동기화 때 다시 나타날 수 있습니다(관점과 같은 합치기 방식).
- 회고 리포트를 끄는 설정은 넣지 않았습니다. 분석 화면에 들어갈 때만 보이고 알림이 없기 때문입니다.

확인 범위: 자동 검사(`npm test`, 실제 Gemini 호출 없음)와 375px 브라우저에서 합성 기록으로 90일 전 생각 카드, 덧붙이기와 생각의 흐름, 나중에·다시 보지 않기, 원칙 만들기(초안 안내·반복 단어 힌트), 근거로 추가, 문장 수정 이력, 지난달 기본 선택, 가짜 AI 응답으로 회고 요약과 원칙 연결, 가로 넘침 없음, 콘솔 오류 없음을 확인했습니다.

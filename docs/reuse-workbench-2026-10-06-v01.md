# MEMOIVE · 지난 기록을 이번 작업에 이어 쓰기

## 구현 범위

새 작업에서 작업 이름·목적·선택 자료·관점·초안·자료별 활용 역할과 제외 이유를 기존 기기 저장소에 보관한다. 오늘 화면과 창작 화면에서 작업을 이어 열 수 있다. 작성 중 작업은 완성된 결과물 집계에 포함하지 않는다.

| 사용자 부담 | 구현 |
| --- | --- |
| 목적과 관점을 반복 설명 | 작업 복원, 다른 작업의 목적·관점을 확인 후 가져오기 |
| 어떤 자료를 쓸지 찾기 | 목적·검색어와 제목/주제/생각/본문의 단어 일치, 일치 이유와 본문 일부 표시 |
| 자료 선택 이유를 잊음 | 참고/근거 후보/반례 후보/방법 후보를 직접 선택, 활용·제외 메모 보관 |
| 생각을 다시 타이핑 | 선택 기록의 기존 생각을 그대로 관점에 추가, 중복 추가 방지 |
| 자동 본문 읽기 실패로 흐름 중단 | 선택 자료의 빈 본문을 창작 화면에서 직접 붙여 넣기, 상세 확인 후 작업 복귀 |
| 결과물의 출처를 다시 찾음 | 결과물 문장과 저장 본문의 정확한 발췌를 직접 연결, 원문 링크·문장 성격 보관 |
| 문장 수정 후 근거가 어긋남 | 현재 결과물에 문장이 없거나 현재 본문에서 발췌를 찾지 못하면 재확인 표시 |
| 다른 편집기에 재료 이동 | 목적·관점·자료 요약·생각·활용 메모·연결 근거를 한 번에 복사 |

## 사실·의견·추천 구분

- 추천은 기기 내 단어 일치다. 의미 검색, AI의 타당성 판정, 반례 자동 발견으로 소개하지 않는다.
- 예시는 자동 추천 후보에서 제외한다. 전체 기록에서 직접 선택할 수 있다.
- 사용자가 자료의 역할을 지정한다. 단어가 겹친다는 이유로 뒷받침 근거/반례라고 단정하지 않는다.
- 발췌는 저장 본문에 그대로 존재해야 한다. 원문에 관한 주장 / 해석·적용 제안 / 내 의견을 직접 구분한다.
- 발췌가 본문에 있다는 것만 검사하며 주장의 타당성이나 인과를 증명하지 않는다.
- 기존 기록의 생각을 그대로 재사용한다. 기존 합쳐진 저장 이유·생각을 임의로 분리하거나 새 사용자 의견을 생성하지 않는다.
- 본문 불러오기 제한을 우회하지 않는다. 수동 본문도 사용자가 제공한 내용이며 독립적으로 진위를 검증한 것은 아니다.

## 보관과 AI

- 기존 이 브라우저 보관 방식 유지. 로그인/클라우드 동기화 도입 없음.
- workspaces는 기존 백업 내보내기/가져오기에 포함된다. 동일 ID는 현재 자료를 우선한다. 결과물은 문장 근거 연결을 보관한다.
- 저장 공간 오류/동시 탭 충돌 시 기존 저장본 보호. 저장 실패를 표시하며 화면 입력을 유지한다.
- 자료 추천·활용 메모·근거 연결은 외부 전송을 하지 않는다. Gemini는 기존 실행 전 동의 흐름을 유지한다.
- 활용 역할/제외 메모는 AI 프롬프트에 자동 전송하지 않는다. 필요하면 사용자가 목적에 반영하거나 자료 묶음으로 복사할 수 있다.
- 이전 동의를 새 작업에 자동 재사용하지 않는다. 원문 포함 선택은 작업을 열 때 해제한다.
- 기존 서버 입력 제한에 맞춰 8개 자료/목적 600자/관점 1,200자/기록별 생각 1,000자 초과 시 조용히 잘라 보내지 않고 정리 요청.
- 요청 도중 목적·초안·자료·생각이 바뀌면 이전 AI 응답을 적용하지 않는다.

## 확인

합성 기록으로 작업 재열기·새로고침, 생각 재사용, 역할/제외 이유, 빈 본문 채우기, 없는 인용 거부, 결과물 저장 및 근거 보존, 문장 변경 경고, 작업 백업 정규화, 모의 AI 응답과 오래된 응답 미적용을 검사했다.
320/375/768/1280 너비의 가로 넘침과 기존 저장·동의·요약 검사를 확인했다.
실제 사용자의 시간 단축, 실제 Gemini 출력 품질, 모든 외부 사이트의 본문 자동 읽기 성공을 검증한 결과가 아니다.

## 사용자 확인 흐름

창작에서 새 결과물 만들기 → 목적 입력 → 관련 자료 찾기 → 자료 선택 → 기존 생각을 관점에 추가 → 닫기 → 오늘 화면에서 작업 이어 열기.
실제 결과물을 작성한 다음 문장을 선택해 본문의 발췌와 연결한다. 문장을 고치면 근거 재확인 표시를 확인한다.

# MEMOIVE v2.0 사용 검증 준비물

작성일: 2026-10-14 · [제품 기획서 v2.0](PRD_MEMOIVE_2026-10-14-v2.0.md) 9장을 실행하기 위한 준비물입니다. 결과는 아직 없습니다.

## 원칙
- 검증은 사람이 직접 수행한 결과만 셉니다. AI 도구가 대신 조작한 시험, 합성 자료, 예시 기록은 사용 결과로 세지 않습니다.
- 같은 사람이 여러 번 해도 참여자는 1명입니다. 참여자 수, 기기, 버전, 자료 조건을 결과와 함께 적습니다.
- 3~5명 결과는 방향을 보는 단서이며 통계적 효과로 주장하지 않습니다.
- 참여자의 실제 기록 내용, 이름, 연락처는 저장소에 올리지 않습니다. 결과에는 과제별 완료 여부, 시간, 막힌 지점 요약만 씁니다.

## 0. 변경 전 기준값 (v1)
v2.0은 2026-10-14에 운영에 배포되어 운영 사이트로는 v1을 잴 수 없습니다. 아래 두 과제는 AI가 필요 없으므로, v1 마지막 커밋 `c3505e5`를 로컬에서 띄워 측정할 수 있습니다.

```sh
git worktree add ../memoive-v1 c3505e5
python -m http.server 4183 --directory ../memoive-v1
```

브라우저에서 http://127.0.0.1:4183/ 를 열어 아래 과제를 합니다. 로컬 주소는 운영과 저장 공간이 따로라서 기존 기록에 영향이 없습니다. 끝나면 `git worktree remove ../memoive-v1`로 지웁니다.

| 과제 | v1에서 하는 방법 | 비교할 것 |
|---|---|---|
| 연관 기록 이유 설명 | 기록 상세의 "함께 보면 이어지는 기록"에서 하나를 골라 이유를 설명 | 이유를 화면 근거로 설명했는지, 걸린 시간 |
| 생각 남기기 | 새 자료를 저장하고 "내 생각"을 한 줄 이상 남김 (v1에는 질문 받기 없음) | 생각 글자 수, 걸린 시간, 막힌 지점 |

v1 화면의 `내 기록 분석 → 내 사용 테스트`에서 버전을 `v1`으로 적고 기록한 뒤 결과 파일을 내려받습니다. 운영(v2.0)에서 같은 과제를 다시 하고 버전을 `v2.0`으로 적습니다. 저장 공간이 달라 회차 연결 기능은 쓸 수 없으니, 두 결과 파일을 나란히 비교합니다. 로컬 실행이라는 조건 차이도 함께 적습니다.

## 1. 제작자 반복 사용 (1명)
배포 후 `내 사용 테스트`에서 과제를 골라 수행합니다. v2 과제는 `v2 ·`로 시작합니다.

| 순서 | 과제 | 간격 |
|---|---|---|
| 1 | v2 · 내 관점으로 기록 | 첫날 |
| 2 | v2 · 질문 받고 생각 남기기 | 첫날, 자료 2개 이상 |
| 3 | v2 · 연관 기록 이유 설명 | 첫날 (v1 기준값과 비교) |
| 4 | v2 · 예전 생각에 덧붙이기 | 3일 이상 지난 뒤 |
| 5 | v2 · 기록에서 원칙 만들기 | 생각을 남긴 기록이 5개 이상 쌓인 뒤 |

결과 파일은 도구에서 JSON·CSV로 내려받아 비공개로 보관합니다.

## 2. 외부 참여자 (희망자 3~5명)

### 모집 메시지 초안
> 지난번 MEMOIVE 시연에 의견 주셔서 감사합니다. 주신 의견(관점 직접 만들기, 질문으로 생각 구체화, 추천 이유, 리마인드 등)을 반영해 새 버전을 만들었습니다. 20분 정도 직접 써 보시면서 막히는 곳을 확인하고 싶은데, 참여해 주실 수 있을까요? 개인 기록 내용은 수집하지 않고, 과제를 마쳤는지와 막힌 지점만 기록합니다. 원하지 않으시면 언제든 중단하셔도 됩니다.

### 진행 방법
1. 서비스 주소만 알려주고 기능 설명은 하지 않습니다.
2. 아래 과제를 한 번에 하나씩 보여줍니다. 참여자가 평소 저장해 둔 글이나 영상 하나를 쓰게 합니다.
3. 진행자는 화면을 보며 기록표만 채우고, 막혀도 3분 동안은 돕지 않습니다. 도움을 줬다면 "도움 후 완료"로 적습니다.
4. 끝나고 두 가지만 묻습니다: "가장 막힌 곳은?", "다음 주에도 쓸 것 같은 기능은?"

### 참여자 과제
| 번호 | 과제 문장 (참여자에게 보여줌) | 완료 기준 (진행자만 봄) |
|---|---|---|
| A | 평소 저장해 둔 글이나 영상 하나를 기록하고, 떠오른 생각을 남겨 주세요. | 생각이 1문장 이상 저장됨. 질문 받기를 스스로 찾았는지 함께 적음 |
| B | 내 상황에 맞는 관점을 하나 만들어 그 관점으로 생각을 남겨 주세요. | 사용자 정의 관점으로 생각 저장 |
| C | 방금 기록과 이어지는 다른 기록을 찾고, 왜 이어지는지 말해 주세요. | 화면 근거로 이유 설명 |
| D | 휴대폰에서 다른 앱의 공유 메뉴로 링크 하나를 저장해 보세요. (휴대폰 참여자만) | 공유로 저장 성공. 설치 안내를 스스로 찾았는지 적음 |

## 3. 지표 계산 (PRD 4장)
제작자 기기의 백업 JSON(설정의 `기록 보관함 → 백업 내려받기`)의 `analytics.events`와 `records`로 계산합니다. 예시 기록은 제외합니다.

| 지표 | 계산 |
|---|---|
| 북극성: 다시 돌아와 생각을 덧붙인 기록 비율 | 저장일보다 뒤의 날짜에 생각을 덧붙이거나 고친 기록 수 ÷ 기록 수 (`DataTools.revisitedThought`) |
| 질문 응답률 | `question_answered`가 있는 기록 수 ÷ `question_shown`이 있는 기록 수 |
| 생각 작성 비율 | 생각이 있는 기록 ÷ 기록 수 |
| 사용자 정의 관점 사용률 | `thought_saved` 중 값이 `custom`인 비율 |
| 리마인드 반응률 | `thought_followup` 수 ÷ `memory_shown` 수 |
| 원칙 생성 수 | 근거 기록 2개 이상인 원칙 수 |
| 안내 수락률 | `hint_accepted` ÷ `hint_shown` (안내 종류별) |

주의: 추천에서 연 기록을 구분하는 이벤트는 아직 없어 추천 클릭률은 계산할 수 없습니다.

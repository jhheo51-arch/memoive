# MEMOIVE 구현 및 검증 상세

README의 첫 화면을 간결하게 유지하기 위해 저장 구조, AI 사용, 입력 통로와 운영 주의사항을 이 문서에 모았습니다.

## 하나의 기록 저장소

`memoive.vercel.app`의 기록 보관함에서 소유자 연결 코드를 입력하면 TOBEA Supabase를 기준 저장소로 사용합니다. 최초 기준 데이터는 2026-10-07에 화면에서 확인한 기록 13개와 결과물 2개의 JSON 백업입니다. 연결한 브라우저는 Supabase 기록을 먼저 불러오고 이후 저장과 수정 내용을 짧게 모아 서버에 반영합니다. 연결 직전의 브라우저 기록은 별도 로컬 복구본으로 남깁니다.

Supabase 표와 원본 파일 보관함은 공개 읽기를 막고, Vercel의 `/api/sync`와 `/api/original`이 소유자 코드를 확인한 뒤 접근합니다. 소유자 원문 코드는 저장소나 배포 코드에 포함하지 않고 Vercel에는 SHA-256 해시만 비밀 환경변수로 보관합니다. 다른 화면에서 동시에 수정해 저장 버전이 달라지면 덮어쓰지 않고 최신 기록을 다시 불러오도록 안내합니다.

Vercel, Cloudflare Pages와 GitHub Pages 같은 다른 화면 주소도 같은 Vercel API를 사용하도록 설정할 수 있습니다. 새 주소나 새 브라우저에서는 `다른 기기 연결 링크 복사`로 만든 링크를 한 번 열어야 같은 개인 기록에 연결됩니다. 이는 한 사람의 여러 브라우저를 위한 동기화이며 여러 사람이 함께 편집하는 기능은 아닙니다.

## AI 사용 기준

MEMOIVE가 Codex보다 분석을 더 정확하게 하거나 더 좋은 글을 쓴다는 근거는 아직 없습니다. 차별화 가설은 같은 사용자의 기록, 생각, 출처와 진행 중인 글을 한 흐름에 보관해 다시 쓰는 수고를 줄이는 것입니다.

Gemini를 사용하면 화면에서 전송 범위를 확인하고 동의한 자료가 Cloudflare Worker를 거쳐 Google로 전달됩니다. AI는 사용자가 직접 고친 초안만 편집 기준으로 받으며, AI 응답이 직접 고친 글을 자동으로 덮어쓰지 않습니다. 비공개 자료나 민감한 자료를 넣기 전에 전송 범위를 확인해야 합니다.

같은 자료와 동일한 글쓰기 과제로 MEMOIVE와 다른 도구를 비교하려면 다음을 확인해야 합니다.

- 원문과 다른 내용이 포함되는 빈도
- 사용자의 생각이 최종 글에 남는 정도
- 완성까지 걸린 시간
- 며칠 뒤 작업을 다시 시작할 수 있는지

## 공개 글과 영상 입력

공개 글 주소는 본문 읽기 서비스인 Jina AI Reader로 전달됩니다. 일부 사이트의 자동 본문 읽기가 제한되면 주소와 사용자의 생각을 먼저 보존하고 본문을 직접 붙여 넣을 수 있습니다.

유튜브 링크는 일반 웹페이지의 글을 영상 발언으로 오인하지 않고 공개 자막을 먼저 요청합니다. Vercel에서는 `/api/youtube-transcript` 서버 통로를 사용하고, 실패하면 기존 공개 자막 경로를 한 번 더 시도합니다. 일반 주소, 단축 주소, Shorts, Live, 임베드와 YouTube Music 주소를 영상으로 분류합니다.

자막이 없거나 외부 자막 서비스가 실패하면 기록 상세의 `스크립트 직접 붙여 넣기`를 사용할 수 있습니다. 자동 생성 자막에는 오인식이 있을 수 있으며, 영상 화면 자체를 이해하거나 발언의 정확성을 검증한 결과는 아닙니다.

긴 스크립트와 PDF는 60,000자까지 분석하며 이를 넘으면 화면에서 분석할 부분을 직접 고르게 합니다. 외부 자막 서비스의 무료 경로는 개인 시제품의 낮은 사용량을 위한 것이며 상용 서비스 수준의 안정성을 보장하지 않습니다.

## 확인한 범위

- 공개 영상 두 건에서 자막 통로 응답 확인
- 잘못된 영상 ID, 다른 영상의 자막 혼입과 예상하지 않은 응답 차단 검사
- 저장 실패 시 입력 보존과 성공 시 입력 초기화 검사
- 동시 수정, 손상된 저장 자료, 백업 복원과 오래된 결과물 덮어쓰기 차단 검사
- 공개 원문, AI 해석과 사용자 생각의 분리 검사

위 검사는 코드 조건과 합성 자료에 관한 것입니다. 외부 사용자의 만족도, 글 품질 향상과 장기간 반복 사용 효과는 아직 확인하지 못했습니다.

## 제출 및 운영 기준

보여줄 핵심은 기능 수가 아니라 왜 저장 개수보다 다시 쓴 글을 중요하게 보았는지, 직접 사용하며 발견한 막힘을 어떻게 바꿨는지입니다. 실제 사용 사례를 남길 때는 자료 제목과 민감한 원문을 공개하지 않아도 됩니다.

공개 저장소에는 시연 자료만 포함합니다. 실제 개인 기록은 기기 저장 공간과 소유자 연결로 보호되는 비공개 저장소에 보관하며, API 키는 저장소에 포함하지 않습니다.

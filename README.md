# MEMOIVE — 기록을 내 글로 이어 쓰는 웹 서비스

[서비스 사용하기](https://memoive.vercel.app/) | [제품 기획서](docs/PRD_MEMOIVE_2026-10-06-v01.md) | [검증 범위](docs/verification.md) | [발표용 요약](docs/submission-presentation-2026-10-07-v01.md)

![MEMOIVE 운영 화면](assets/project-overview.png)

## 1. 문제 정의

자료를 저장해도 왜 저장했는지 잊고, 필요한 순간 다시 찾거나 실제 글과 기획에 활용하기 어렵다는 문제에서 시작했습니다. 초기 대상은 제품 사례와 참고 자료를 모아 기획안, 포트폴리오와 글을 쓰는 사람입니다.

## 2. 자료와 가정

제작자의 반복 사용에서 발견한 불편, 공개 글과 영상의 입력 사례, 개인정보가 없는 합성 시험 자료를 사용했습니다. 외부 사용자의 대표 수요나 경쟁 우위가 확인됐다고 가정하지 않았고, 공개 원문, AI 해석과 사용자 생각을 구분해 저장하도록 설계했습니다.

## 3. 지표 분석

| 확인할 지표 | 현재 확인한 범위 | 해석 주의점 |
|---|---|---|
| 입력 성공과 원문 보존 | 공개 글, 영상 자막과 긴 본문의 입력 경로 및 실패 시 직접 입력 확인 | 모든 사이트와 영상에서 성공한다는 뜻은 아님 |
| 저장 안정성 | 저장 실패, 용량 초과, 동시 수정과 백업 복원 합성 검사 통과 | 장기간 실제 사용 안정성은 별도 관찰 필요 |
| 기록의 재사용 | 기준 데이터 13개 기록과 결과물 2개의 동기화 동작 확인 | 기록 수가 글쓰기 효과나 만족도를 증명하지 않음 |
| 완성까지 걸린 시간 | 측정 방법만 설계 | 외부 사용자 비교 결과는 아직 없음 |

## 4. 내가 한 판단

‘얼마나 많이 저장했는가’보다 **내 생각이 남았는가, 다시 찾았는가, 실제 결과물로 이어졌는가**를 더 중요한 기준으로 정했습니다. AI가 대신 완성하는 제품보다 원문, AI 해석과 사용자 의견을 분리하고, 사용자의 생각이 최종 글에 남는 흐름을 선택했습니다.

## 5. 작동 화면

운영 서비스에서 `기록하기 → 내 생각 남기기 → 다시 찾기 → 글로 이어 쓰기` 흐름을 확인할 수 있습니다. 첫 초안은 기기에서 바로 만들고, 사용자가 원할 때만 AI 표현 제안을 별도로 받습니다.

### 3분 시연

1. 공개 글 주소나 직접 작성한 텍스트를 저장합니다.
2. 요약, 근거와 해석을 확인하고 `내 생각`을 남깁니다.
3. 내 생각의 단어로 기록을 다시 찾습니다.
4. 기록 또는 내 생각에서 글쓰기를 시작합니다.
5. 수정한 글을 저장한 뒤 다시 열어 참고 기록과 본문이 유지되는지 확인합니다.

## 6. 검증 결과

저장, 검색, 백업, 동기화, 본문 읽기, AI 동의와 출처 보존을 합성 자료로 자동 검사합니다. GitHub 자동검사와 운영 배포를 통과했지만, 이는 코드 조건과 연결 상태를 확인한 결과이며 글 품질이나 사용자 만족도 검증은 아닙니다.

| 발견한 문제 | 선택한 대응 | 확인한 범위 |
|---|---|---|
| 영상 페이지의 글만 읽으면 실제 발언을 분석하지 못함 | 공개 자막을 먼저 가져오고 실패 시 직접 입력 제공 | 공개 영상의 자막 통로 응답 확인 |
| 일부 공개 글의 자동 본문 읽기가 제한됨 | 발행자가 제공하는 공개 피드에서 본문 수집 | 해당 글의 제목과 본문 응답 확인 |
| 28,204자 PDF가 기존 입력 제한에 걸림 | 화면과 분석 서버의 입력 상한을 60,000자로 통일 | 운영 서버에서 시험 본문 분석 성공 |
| PC와 iOS의 기록이 분리됨 | 소유자 연결을 사용하는 비공개 온라인 저장소 도입 | 기준 기록 13개, 결과물 2개와 온라인 저장 동작 확인 |
| PDF 제목이 비어 보임 | 보이지 않는 문자를 제거하고 본문 제목으로 복구 | 시험 PDF 제목 표시 확인 |

## 7. 아직 확인하지 못한 것

- 처음 쓰는 사용자 3~5명이 설명 없이 핵심 흐름을 완료할 수 있는지
- 기존 메모 도구보다 다시 찾기와 글 완성 시간이 실제로 줄어드는지
- 실제 iOS와 Android 기기의 공유, 음성, 키보드와 접근성 동작
- 다양한 자료에서 AI 해석과 인용이 의미상 정확한지

## 구현 범위와 한계

| 영역 | 현재 동작 | 한계 |
|---|---|---|
| 입력 | 텍스트, 공개 링크, 유튜브 공개 자막, 이미지 문자 인식과 음성 입력 경로 | 유료 글, 로그인 글과 자막 없는 영상의 본문 추출을 보장하지 않음 |
| 분석 | 원문 인용을 검사하며 요약, 질문과 적용 제안 표시 | 인용의 존재가 해석 전체의 정확성을 뜻하지 않음 |
| 탐색 | 제목, 생각과 본문 내용의 단어 검색 및 주제와 날짜 보기 | 의미 검색이나 개인화 추천 모델은 아님 |
| 창작 | 두 시작 경로, 편집 가능한 초안, 출처 연결, 저장과 공유용 이미지 | 완성된 글의 품질이나 게시 성과를 보장하지 않음 |
| 보관 | 기기 저장, JSON 백업, 소유자 연결을 사용하는 TOBEA Supabase 동기화 | 로그인 계정 체계가 아니며 새 브라우저에서는 연결 링크가 필요함 |
| 검증 | 자동 점검과 제작자용 사용 시험 | 실제 반복 사용 효과가 입증된 것은 아님 |

```sh
python -m http.server 4182 --directory .
```

전체 합성 검사는 `node scripts/check.mjs`로 실행합니다. 정적 화면은 API 키 없이 열리지만, 운영 AI 서버는 허용된 사이트 주소만 받으므로 로컬 AI 호출은 거절될 수 있습니다.

## 저장소 구조

| 폴더 | 내용 |
|---|---|
| `frontend/` | 화면, 기록, 검색, 창작과 모바일 대응 |
| `api/` | Vercel 동기화, 원문과 자막 통로 |
| `cloudflare-worker/` | Gemini 분석 및 창작 서버 |
| `assets/` | 아이콘과 소개 이미지 |
| `docs/` | 기획서, 검증 문서와 발표자료 |
| `tools/self-test/` | 직접 확인하는 기능 점검 화면 |
| `tests/`, `scripts/` | 자동검사와 로컬 실행 도구 |

제작자는 문제, 표현, 기록 흐름과 개선 우선순위를 판단했고, Codex는 코드 수정과 기술 검사를 보조했습니다. 공개 가능한 시연 기록만 포함하며 실제 개인 기록과 API 키는 GitHub에 올리지 않습니다.

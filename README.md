## 1. 문제 정의

자료를 저장해도 왜 저장했는지 잊고, 필요한 순간 다시 찾거나 실제 글과 기획에 활용하기 어렵다는 문제에서 시작했습니다. 초기 대상은 제품 사례와 참고 자료를 모아 기획안·포트폴리오·글을 쓰는 사람입니다.

## 2. 자료와 가정

제작자의 반복 사용에서 발견한 불편, 공개 글·영상의 입력 사례, 개인정보가 없는 합성 시험 자료를 사용했습니다. 외부 사용자의 대표 수요나 경쟁 우위가 확인됐다고 가정하지 않았고, 공개 원문·AI 해석·사용자 생각을 구분해 저장하도록 설계했습니다.

## 3. 지표 분석

| 확인할 지표 | 현재 확인한 범위 | 해석 주의점 |
|---|---|---|
| 입력 성공과 원문 보존 | 공개 글·영상 자막·긴 본문 입력 경로와 실패 시 직접 입력 확인 | 모든 사이트와 영상에서 성공한다는 뜻은 아님 |
| 저장 안정성 | 저장 실패·용량 초과·동시 수정·백업 복원 합성 검사 통과 | 장기간 실제 사용 안정성은 별도 관찰 필요 |
| 기록의 재사용 | 기준 데이터 13개 기록과 결과물 2개의 동기화 동작 확인 | 기록 수가 글쓰기 효과나 만족도를 증명하지 않음 |
| 완성까지 걸린 시간 | 측정 방법만 설계 | 외부 사용자 비교 결과는 아직 없음 |

## 4. 내가 한 판단

‘얼마나 많이 저장했는가’보다 **내 생각이 남았는가, 다시 찾았는가, 실제 결과물로 이어졌는가**를 더 중요한 기준으로 정했습니다. AI가 대신 완성하는 제품보다 원문·AI 해석·사용자 의견을 분리하고, 사용자의 생각이 최종 글에 남는 흐름을 선택했습니다.

## 5. 작동 화면

운영 서비스에서 `기록하기 → 내 생각 남기기 → 다시 찾기 → 글로 이어 쓰기` 흐름을 확인할 수 있습니다. 첫 초안은 기기에서 바로 만들고, 사용자가 원할 때만 AI 표현 제안을 별도로 받습니다.

## 6. 검증 결과

저장·검색·백업·동기화·본문 읽기·AI 동의·출처 보존을 합성 자료로 자동 검사합니다. GitHub 자동검사와 운영 배포를 통과했지만, 이는 코드 조건과 연결 상태를 확인한 결과이며 글 품질이나 사용자 만족도 검증은 아닙니다.

- 기존 메모 도구보다 다시 찾기와 글 완성 시간이 실제로 줄어드는지

제작자는 문제·표현·기록 흐름과 개선 우선순위를 판단했고, Codex는 코드 수정과 기술 검사를 보조했습니다. 위 확인은 기능 동작에 관한 것이며 사용자 만족도나 글 품질 향상 수치를 측정한 결과는 아닙니다.

MEMOIVE는 읽고 저장한 자료에 **내 생각**을 남기고, 나중에 다시 찾아 **내가 쓸 글**로 이어가는 모바일 중심 웹 서비스입니다. AI가 글을 대신 완성하는 것보다 원문, AI의 해석, 사용자 의견을 구분하고 사용자의 생각이 결과물에 남도록 하는 데 초점을 맞췄습니다.

이 독립 저장소의 `main`이 [MEMOIVE 운영 서비스](https://memoive.vercel.app/)의 배포 원본입니다. 공개 가능한 시연 기록만 코드에 포함하며, 외부 기사 원문 전체와 실제 개인 기록은 GitHub에 올리지 않습니다. 개인 기록은 브라우저 저장 공간과 소유자 코드로 보호되는 TOBEA Supabase에 보관합니다.

## 해결하려는 문제와 대상

문제 가설은 “자료를 저장해도 왜 저장했는지 잊고, 필요한 순간 다시 찾거나 실제 글에 활용하기 어렵다”입니다. 먼저 제품 사례와 레퍼런스를 모아 기획안·포트폴리오·글을 쓰는 사람을 대상으로 삼았습니다. 제작자 자신의 필요에서 시작했으며, 외부 사용자 수요나 경쟁 우위가 입증된 것은 아닙니다.

핵심 가치는 **저장 → 원문과 근거 확인 → 내 생각 작성 → 다시 찾기 → 글로 이어 쓰기**입니다. 창작은 `기록에서 시작하기`(기록의 ‘다시 쓸 방법’ 활용)와 `내 생각으로 시작하기` 두 입구를 제공합니다. 초안은 편집·저장·재열기가 가능하고, 참고 기록으로 돌아갔다가 작성 중인 글로 복귀할 수 있습니다.

`글로 이어보기`는 외부 AI를 기다리지 않고 이 기기에서 즉시 편집 가능한 짧은 초안을 만듭니다. 입력한 생각을 문단으로 나누거나 기록의 ‘다시 쓸 방법’을 출발점으로 삼으며, 적지 않은 경험을 만들지 않습니다. 더 다른 표현이 필요하면 초안 아래의 `AI로 표현 제안 받기 · 선택`을 눌러 별도 제안을 받을 수 있습니다. 손대지 않은 빠른 초안은 AI에 기존 원고로 전달하지 않으며, 사용자가 직접 고친 초안만 편집 기준으로 전달합니다. AI는 생각의 출발·전개·마무리를 별도로 작성하고 화면에는 문단으로 조합해 제안합니다. AI 응답은 직접 고친 글을 덮어쓰지 않습니다. 빠른 초안은 의미를 새로 해석한 AI 글이 아니라 사용자가 고칠 수 있는 출발점입니다.

## 3분 시연

1. `기록하기`에서 공개 글 주소 또는 직접 작성한 텍스트를 저장합니다. 링크 본문 자동 읽기가 실패해도 주소를 먼저 남기고 본문을 직접 붙여 넣을 수 있습니다.
2. 기록 상세에서 자료 정보·요약·근거·해석·질문·‘다시 쓸 방법’을 확인하고 `내 생각`을 한 줄 남깁니다. 원문 링크로 자료를 직접 대조합니다.
3. `기록`에서 방금 쓴 생각의 단어로 기록을 찾아봅니다. 내 기록과 제공 예시는 구분됩니다.
4. `창작`에서 `기록에서 시작하기`를 선택해 ‘다시 쓸 방법’과 내 생각을 글에 반영하거나, `내 생각으로 시작하기`에서 자유롭게 씁니다.
5. 글을 수정·저장한 뒤 다시 열어 참고 기록과 본문이 유지되는지 확인합니다. 필요하면 기록과 결과물을 JSON 파일로 백업합니다.

기본 기록 5개와 제품 사례 3개는 사용법 예시입니다. 제작자의 실사용 성과나 자동 추천 결과가 아닙니다. 예시 기록도 이 기기의 목록에서 삭제할 수 있습니다.

| 탐색 | 제목·생각·본문 내용 등의 단어 검색, 주제·날짜 보기 | 의미 검색이나 개인화 추천 모델은 아님 |

| 다시 보기 | 설정한 날짜와 질문 주기에 따라 앱을 열 때 기록을 보여주고 조건이 맞으면 기기 알림 | 앱을 닫아도 정해진 시각에 반드시 오는 예약 푸시는 아님 |
| 보관 | 브라우저 기기 저장, JSON 백업·가져오기, 소유자 코드로 연결하는 TOBEA Supabase 동기화 | 로그인 계정 체계는 아니며 새 브라우저에서는 연결 링크를 한 번 열어야 함 |
| 검증 | 자동 점검과 제작자용 사용 테스트·기획 근거 기록 도구 | 도구가 있다고 실제 반복 사용 효과가 입증되는 것은 아님 |

공개 글 주소는 본문 읽기 서비스(Jina AI Reader)로 전달됩니다. 유튜브 링크는 영상 ID가 [youtube-transcript.ai](https://youtube-transcript.ai/youtube-transcript-api)로 전달되어 공개 자막을 요청합니다. Gemini를 사용하면 전송 범위를 화면에서 확인하고 동의한 자료가 Cloudflare Worker를 거쳐 Google로 전달됩니다. 2026-10-06 개인 정보가 없는 시험 문장 한 건에서 현재 분석 형식의 응답을 확인했지만, 이는 다양한 글의 정확도나 창작 품질 검증이 아닙니다. 비공개·민감 자료를 넣기 전에 전송 범위를 확인해야 합니다. API 키는 이 저장소에 없습니다. 브라우저 저장 공간 삭제, 기기 변경, 공용 기기 사용에는 별도 주의가 필요합니다.

### 하나의 기록 저장소 (2026-10-07)

`memoive.vercel.app`의 기록 보관함에서 소유자 연결 코드를 입력하면 TOBEA Supabase를 기준 저장소로 사용합니다. 최초 기준 데이터는 2026-10-07에 화면에서 확인한 기록 13개와 결과물 2개의 JSON 백업입니다. 연결한 브라우저는 Supabase 기록을 먼저 불러오고, 이후 저장·수정 내용을 짧게 모아 서버에 반영합니다. 연결 직전의 브라우저 기록은 별도 로컬 복구본으로 남깁니다.

Supabase 표와 원본 파일 보관함은 공개 읽기를 막고, Vercel의 `/api/sync`와 `/api/original`이 소유자 코드를 확인한 뒤 접근합니다. 소유자 원문 코드는 저장소나 배포 코드에 포함하지 않고 Vercel에는 SHA-256 해시만 비밀 환경변수로 보관합니다. 동시에 다른 화면에서 수정해 저장 버전이 달라지면 덮어쓰지 않고 최신 기록을 다시 불러오라는 오류를 표시합니다. Vercel, Cloudflare Pages, GitHub Pages 같은 다른 화면 주소도 같은 Vercel API를 사용하도록 설정할 수 있습니다. 다만 새 주소나 새 브라우저에서는 `다른 기기 연결 링크 복사`로 만든 링크를 한 번 열어야 같은 개인 기록에 연결됩니다. 이는 한 사람의 여러 브라우저를 위한 동기화이며 여러 사람이 함께 편집하는 협업 기능은 아닙니다.

## AI와 Codex 비교에 대해

MEMOIVE가 Codex보다 분석을 더 정확하게 하거나 더 좋은 글을 쓴다는 근거는 **아직 없습니다**. 메모이브의 차별화 가설은 같은 사용자의 기록·생각·출처·진행 중인 글을 한 흐름에 보관해 다시 쓰는 수고를 줄이는 것입니다. 이를 주장하려면 같은 자료와 동일한 글쓰기 과제로 MEMOIVE와 Codex를 각각 사용해, 원문 오류·사용자 생각 보존·완성까지 걸린 시간·며칠 뒤 재개 가능성을 비교해야 합니다. 제품 기준은 [제품 기획서](docs/PRD_MEMOIVE_2026-10-06-v01.md)에, 기획·사용 검증 방식은 [기획 근거](docs/planning-evidence-2026-10-06-v01.md)에 남겨 두었습니다.

## 직접 실행·검사

Python이 있다면 이 `memoive` 폴더에서 아래 명령을 실행하고 `http://127.0.0.1:4182/`를 여세요. 정적 화면은 API 키 없이 실행되지만, 운영 Gemini 서버는 허용된 사이트 주소만 받을 수 있어 로컬 실행의 AI 호출은 거절될 수 있습니다.

```sh
python -m http.server 4182 --directory .
```

주요 자동 점검은 `node tests/submission-self-check.cjs`, `node tests/navigation-order-check.cjs`, `node tests/link-body-check.cjs`, `node tests/capture-reset-check.cjs`로 실행합니다. 저장 실패 때 입력 보존·성공 뒤 초기화를 확인하며, 로컬 브라우저 환경에서는 `tests/writing-speed-browser.cjs`로 첫 초안이 AI 왕복 없이 즉시 나타나는지도 확인합니다. 이는 코드 조건 검사이지 실제 사용자 만족도나 글 품질 검증은 아닙니다. 제작자 반복 사용 결과와 외부 첫 사용자 테스트는 아직 확보되지 않았습니다. [이전 기술 검증 범위](docs/verification.md), [반복 사용 계획](docs/self-study-plan.md)을 구분해 읽어 주세요.

## 제출 전 제작자의 판단

이번 과제에서 보여줄 핵심은 기능 수가 아니라 **왜 ‘저장 개수’보다 ‘다시 쓴 글’을 중시했는지**, 그리고 직접 사용 중 발견한 막힘을 어떻게 바꿨는지입니다. 실제 사용 사례를 최소 한 건 남길 때는 자료 제목과 민감한 원문을 공개하지 않아도 됩니다. 목적 → 기록 → 내 생각 → 다시 찾아 만든 글 → 불편했던 점 → 수정 여부를 익명화해 적고, 하지 않은 외부 사용자 검증은 완료로 표시하지 않습니다.

## 유튜브 스크립트 기반 기록 (2026-10-06)

유튜브 링크를 저장하면 일반 웹 본문 대신 공개 자막의 스크립트를 먼저 읽습니다. 영상 제목·시각 표시가 있는 스크립트를 보관하고, 이어지는 동일 구절의 중복을 정리한 뒤 기존 근거 기반 분석에 넘깁니다. 예시 영상 `Aj2a5Ru2vMA`에서는 한국어 자동 자막을 가져와 약 1만 6천 자로 정리하는 호출을 확인했습니다. 영상 화면 자체를 이해하거나 발언의 정확성을 검증한 결과는 아닙니다. 자동 생성 자막에는 오인식이 있을 수 있습니다.

자막이 없거나 외부 자막 서비스가 실패하면 제목·재생 화면의 글을 영상 본문으로 오인하지 않고 링크와 내 생각을 보존합니다. 기록 상세의 **스크립트 직접 붙여 넣기**에 사용자가 유튜브에서 복사한 내용을 넣고 분석을 다시 진행할 수 있습니다. 긴 스크립트와 PDF는 AI 입력 상한 60,000자까지 바로 분석하며, 이를 넘으면 화면에서 분석할 부분을 직접 고르게 합니다. 이 외부 서비스의 무료 경로는 개인·시제품의 저사용량 용도이며, 상용 서비스의 안정성을 보장하지 않습니다.

검사: `node tests/link-body-check.cjs`는 URL 위장 차단, 다른 영상의 스크립트 혼입 차단, 접근 제한 페이지의 본문 오인 방지를 확인합니다. 실제 영상 링크의 스크립트 가져오기는 별도 호출로 확인했습니다.

### Vercel 자막 보완 (2026-10-07)

Vercel에서는 브라우저가 외부 자막 요청을 제한하는 경우를 줄이기 위해 `/api/youtube-transcript` 서버 통로를 먼저 사용합니다. 이 통로가 일시적으로 실패하면 기존 공개 자막 경로를 한 번 더 시도합니다. 일반 YouTube·단축 주소·Shorts·Live·임베드·YouTube Music 주소를 영상으로 분류하며, 다른 영상 ID나 자막 형식이 아닌 응답은 저장하지 않습니다. 설치형 앱의 이전 파일이 남지 않도록 현재 서비스 워커 캐시는 버전 76을 사용합니다.

합성 검사는 잘못된 영상 ID, 예상하지 않은 응답, 허용되지 않은 요청 방식, 캐시 설정을 확인합니다. 실제 공개 영상 `Aj2a5Ru2vMA`, `amFzo2JAIlo`는 2026-10-07에 새 서버 통로 코드로 각각 공개 스크립트 응답을 확인했습니다. 영상에 공개 자막 자체가 없거나 자막 제공처가 차단된 경우에는 자동 분석을 보장하지 않으며, 상세 화면의 **스크립트 직접 붙여 넣기**를 사용합니다.
